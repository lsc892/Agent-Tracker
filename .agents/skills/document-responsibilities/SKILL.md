# 폴더·파일·클래스 책임 문서화

폴더 README로 전체 책임 분담을 보고, 소스 파일을 열면 파일과 각 클래스의 책임을 바로 읽을 수 있게 한다. 설명은 한국어 한 줄로 쓴다.

## 작성 형식

- **폴더 `README.md`**: 폴더명 제목, 폴더 역할 한 문장, 직접 하위 파일·폴더의 상대 Markdown 링크와 책임 한 줄씩으로 구성한다. 하위 폴더는 해당 README로 연결한다.
- **단일 클래스 파일**: README에서 파일명·클래스명·책임을 한 줄로 묶는다. 파일 역할과 같은 클래스 역할을 별도 항목으로 반복하지 않는다.
- **여러 클래스가 있는 파일**: 클래스별 책임을 한 줄씩 구분하거나 짧으면 파일 항목 한 줄에 함께 적는다. 클래스가 없는 파일은 파일 책임만 적는다.
- **파일 맨 위**: `// …한다.` 형태의 파일 책임 한 줄을 쓴다. 언어에 맞는 주석 문법을 사용하며 shebang·필수 인코딩 선언의 위치는 유지한다.
- **각 클래스 바로 위**: `/** …한다. */` 형태로 그 클래스가 맡는 책임 한 줄을 쓴다. 실제 선언과 익명 클래스 표현식도 포함하며 문자열 안의 코드는 제외한다.

README 예시:

```markdown
# ui

quota와 사용량 통계를 VS Code 상태바·툴팁·Webview에 표시한다.

- [statusBar.ts](statusBar.ts) — `QuotaStatusBar`: quota 항목·툴팁·새로고침 버튼을 관리한다.
```

소스 예시:

```ts
// quota 상태를 VS Code 상태바 항목과 새로고침 버튼에 반영한다.
import * as vscode from 'vscode';

/** quota 상태바 항목·툴팁·새로고침 버튼의 수명을 관리한다. */
export class QuotaStatusBar implements vscode.Disposable {
```

## 설명 범위

- 이름만 보고 추측하지 않고 실제 구현과 호출 관계를 읽어 책임을 적는다. README는 파일·클래스 사이의 분담을, 파일 머리말은 파일 전체를, 클래스 주석은 해당 클래스의 책임을 설명한다.
- 책임 설명에 메서드 목록·알고리즘 해설·작업 이력을 덧붙이지 않는다. 기존 클래스의 긴 책임·알고리즘 주석은 책임 한 줄로 줄이되 필요한 규격 링크·도구 지시·라이선스와 다른 메서드 주석은 보존한다.
- 기존 사용자용 README는 사용법을 유지하고 소스 역할 목록이나 안내 링크만 필요한 만큼 추가한다.
- 관리하는 원본 코드·도구·테스트와 관련 폴더를 대상으로 한다. 의존성·생성물·캐시는 제외하고, 원본 fixture 데이터와 코드 문자열은 수정하지 않는다. JSON 등 주석을 허용하지 않는 데이터 파일의 역할은 README에서만 설명한다.
- 코드 동작·API·의존 관계·파일 구조는 유지한다. 이 작업을 이유로 함수별 설명을 추가하거나 리팩토링하지 않는다.

## 작업 분담과 검증

- 먼저 요청 범위와 기존 변경을 확인한다. 일부 폴더 요청은 해당 범위에서 끝내고, 전체 정리 요청이면 관리하는 원본 폴더와 하위 폴더를 빠짐없이 살핀다.
- 여러 폴더를 다루면 서브에이전트에게 겹치지 않는 폴더 범위를 맡겨 메인 문맥을 줄인다. 형식·보존 조건·담당 경로를 전달하고, 각 담당자는 직접 읽고 수정한 뒤 경로·개수·검증 결과만 짧게 보고한다. 작은 작업이나 서브에이전트를 쓸 수 없는 경우에는 직접 처리한다.
- 메인은 실제 diff를 검토하고 파일 머리말·클래스 주석의 누락과 중복, README의 책임 설명·상대 링크, 한글 인코딩·기존 줄바꿈 보존을 확인한다. Windows에서 파이프로 파일을 생성할 때는 UTF-8 전달을 명시한다.
- 주석 외 실행 코드가 바뀌지 않았는지 확인하고 [저장소 검증 지침](../../../AGENTS.md)에 따른 검사를 수행한다. 스킬·문서·주석만 정리해 기능 동작이 달라지지 않았다면 의사결정 일지를 추가하지 않는다.
- 완료 시 문서 진입점, 적용 범위와 검증 결과를 간단히 알린다.
