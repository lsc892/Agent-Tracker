# 스레드 사용량 winner 정책

winner는 같은 응답을 여러 번 기록했을 때 사용량 집계에 채택하는 후보 한 건이다. 현재 수집기는 파일 안에서 먼저 응답별로 선택하고, 관련 파일을 읽은 뒤 같은 논리 범위의 후보를 다시 비교한다. 응답의 입력 토큰과 출력 토큰을 더해 점수를 매기며, 합이 JavaScript 안전 정수 범위를 넘으면 BigInt로 비교한다. 채택한 후보의 모델·캐시도 함께 반영한다. [점수 계산](../../src/summary/aggregation/winners.ts)

## 비교 키와 동점 처리

| 범위 | 중복 비교 키 | 선택 순서 |
| --- | --- | --- |
| Claude 파일 내부 | `message.id`, `requestId` | 점수가 큰 행을 고른다. 동점이면 나중 행을 고른다. |
| Claude 여러 파일 | 제공자·세션, `message.id`, `requestId` | 점수, 나중에 등록한 스레드 그룹, 그룹 내 대표 원본, 나중에 처리한 복사본, 나중 행 순으로 비교한다. 요청 ID가 있는 후보가 한 종류일 때만 같은 메시지의 요청 ID 없는 후보와 함께 비교한다. |
| Codex 파일 내부 | `turn_id`, `response_id` | 점수가 큰 행을 고른다. 동점이면 나중 행을 고르되, 누계 비교용 위치는 응답 키가 처음 나온 위치를 유지한다. |
| Codex 여러 파일 | 제공자·세션·스레드, `turn_id`, `response_id` | 점수를 먼저 비교한다. 동점이면 대표 원본의 후보를 우선하고, 대표 후보가 없으면 나중에 병합한 복사본을 사용한다. |

각 스레드의 대표 원본은 식별된 응답의 존재 여부, 중복 제거 전 사용량 기록 수, 최신 수정 시각, 경로 오름차순으로 고른다. 대표 원본의 시간 범위와 Codex 누계를 집계의 기준으로 사용한다. 다른 파일의 응답도 위 비교 규칙에 따라 이길 수 있다. [파일 내부 선택](../../src/summary/parsers/threadUsage.ts) · [파일 간 선택](../../src/summary/scanner/refresh/aggregation.ts)

예를 들어 같은 Codex 턴·응답에 대해 대표 원본이 120토큰, 복사본이 150토큰을 기록했다면 복사본의 150토큰을 반영한다. 두 후보 모두 120토큰이면 대표 원본의 모델과 캐시를 반영한다.

## 선택 이후의 집계와 저장

1. Claude는 세션에서 확정한 응답을 해당 스레드와 모델별로 한 번씩 더한다.
2. Codex는 대표 원본의 구형 누계에서 부모와 일치하는 복사 접두사를 제외한다. 이후 새 형식 winner를 한 번씩 더하고, 응답으로 설명되지 않는 체크포인트 증가분은 같은 턴 누계나 구형 기록으로 검증된 경우에만 보충한다. 부모 원본은 구형 이력이 있어 비교가 필요한 경우 조회한다. [부모 원본 탐색](../../src/summary/scanner/refresh/relations.ts) · [누계 검산](../../src/summary/aggregation/threadAccounting.ts)
3. 스레드별 합계는 메모리에서 제공자·모델별 일별 집계의 입력이 된다. 갱신은 영향 세션의 관련 원본을 다시 읽어 winner를 정하고, 보존 조건을 충족한 소실 원본의 기존 일별 집계는 저장 단계에서 처리한다. [일별 저장](SQLiteTables.md)

JSONL의 필드 경로와 파싱 범위는 [LogParsingFields](LogParsingFields.md), 기능 전체의 설계 기준은 [설계 명세](AgentTracker.md)에 있다.
