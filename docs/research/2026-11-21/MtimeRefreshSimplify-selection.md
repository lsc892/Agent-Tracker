# 수정 시각 대상 선택과 관계 처리 단순화

2026-11-21의 수정 시각 갱신 작업 트리를 기준으로 한다. 디렉터리에서 관측한 파일의 수정 시각으로 파싱 후보를 고르고, 영향 세션과 Codex 관계를 확장한 뒤 기존 winner 순서에 맞춰 집계한다. [탐색](../../../src/summary/scanner/refresh/discovery.ts) · [관계 해소](../../../src/summary/scanner/refresh/relations.ts) · [집계](../../../src/summary/scanner/refresh/aggregation.ts)

| 후보 | 상태 | 변경 범위 |
| --- | --- | --- |
| 선택-01 | 적용 완료 | 저장 원본과 이번 관측을 하나의 경로 색인에서 해소한다. 중첩 루트의 같은 파일에 ID를 한 번 할당하고 마지막 루트의 관측값을 사용한다. |
| 선택-02 | 적용 완료 | 미확인 부모 참조를 모아 후보 파일의 ID 순서 batch를 직접 구성한다. |
| 선택-03 | 적용 완료 | 세션 ID와 탐색 순서를 FileState에서 한 번씩 관리한다. 최종 집계는 준비한 원본에서 변경 원본, 같은 세션의 다른 원본, 선택 루트 밖에서 읽은 원본 순으로 입력을 구성한다. |
| 선택-04 | 적용 완료 | 파싱이 완료된 DTO의 근거·요청 상태·winner를 집계가 직접 읽는다. |

## 선택-01 — 경로별 한 번 등록

SQLite에서 스캔에 사용하는 출처 열을 순회하고 관측 여부도 같은 경로 색인에 기록한다. 원본 수 F와 디렉터리 방문 횟수 V에 대해 등록·누락 판정은 O(F+V)다. 본문 후보나 삭제 영향 세션을 발견한 시점에 관계 색인을 활성화하며, 활성화 시점 전후에 걸쳐 각 파일을 한 번 색인한다. 무변경 갱신은 관계 색인에 원소를 넣지 않는다. 최초 중첩 루트에서는 같은 신규 경로를 두 개의 ID로 등록하던 경우를 회귀 테스트로 검사한다. [탐색과 등록](../../../src/summary/scanner/refresh/discovery.ts) · [중첩 루트 검증](../../../tests/node/summary-lineage.test.ts)

## 선택-02 — 미확인 부모 후보 한 번 선택

부모 참조를 검색하는 동안 다른 파일을 읽거나 참조 상태를 변경하는 작업이 없었다. 아직 검색하지 않은 참조 집합을 소비해 경로가 일치하는 파일을 고르고, 파일 ID 순으로 정렬해 다음 batch로 넘긴다. 최악의 경우 Codex 후보 C개와 새 참조 R개에 대해 O(CR), 일치 파일 P개의 정렬에 O(P log P)가 든다. 여러 참조를 만나도 파일은 한 번 추가한다. 관련 세션의 우선순위 큐는 필요한 원본을 ID 순서로 확장하면서 선행 읽기 범위를 제한한다. [부모와 관련 파일 선택](../../../src/summary/scanner/refresh/relations.ts)

## 선택-03·04 — 준비 결과의 순서와 데이터

과거 순회 순서 Map은 FileState의 탐색 순서로, 파싱 시퀀스 번호는 준비 결과를 기록하는 배열의 삽입 순서로 대체했다. 선택 루트의 winner 비교는 기존 변경 원본 우선과 ID 순서를 사용한다. 세션의 이전 값은 저장 출처에서 읽고 현재 값은 FileState에 한 번 기록한다. 파서가 보낸 DTO에서 값만 소비하므로 집계 전에 파서용 객체와 근거 객체를 복구하는 경로를 삭제했다. 제품과 테스트는 워커가 직렬화하는 동일한 DTO를 집계에 전달한다. 과거 파싱 재개 실험은 당시 버전의 실행기를 사용한다.
