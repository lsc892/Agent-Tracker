# 수정 시각 갱신 저장 경로 정리

2026-11-21 작업 트리의 수정 시각 증분 구현을 기준으로 연결 성분과 원본 행 저장을 검토했다. 스캔 중 연결된 세션은 같은 저장 단위를 이루며, 이름·실패 진단을 마무리한 뒤 성공한 스캔 시작 시각을 확정한다. [갱신 진입점](../../../src/summary/scanner/refresh/index.ts) · [저장 단계](../../../src/summary/scanner/refresh/persistence.ts)

## 저장-01 — 무변경 원본 행의 전체 쓰기 제거

탐색은 스캔의 관측 집합으로 파일 소실을 판단한다. 이전 저장 마무리는 이 판단이나 변경 후보에 쓰이지 않는 `last_seen_scan_id`를 기존 파일마다 갱신했다. 스캔 ID 입력과 테스트만 호출하던 미관측 조회를 제거했다. SQLite 열은 기존 v21 DB와의 호환을 위해 남겨 두었다. 마지막 성공 시각은 이름 갱신과 같은 트랜잭션에서 확정한다. [탐색과 소실 판단](../../../src/summary/scanner/refresh/discovery.ts) · [출처 저장소](../../../src/summary/db/sourceFiles.ts)

선택한 기존 파일 수가 F이면 정상 무변경의 출처 행 UPDATE는 F회에서 0회로 준다. 파일 시스템 탐색과 메모리의 상태 확인은 O(F)다. 기능 검증은 [수정 시각 갱신](../../../tests/node/mtime-refresh.test.ts)과 [원본 이동](../../../tests/node/source-reconnection.test.ts)을 사용한다.

## 저장-02 — 성분 방문, 실패 복구, 갱신 완료를 구분

이전 저장 단계는 대기 성분 집합과 영향 세션 집합을 모두 바꿔 방문 여부를 표시했다. 저장 함수의 작업 집합 하나가 순서를 관리하고, 연결 성분은 삽입 순서로 순회한다. 트랜잭션 묶음의 상한과 개별 재시도를 적용한다. 파일 상태는 한 번 순회하고, 최초 실패 행의 SQLite 자동 ID 할당에 앞서 세션 없는 원본의 예약 ID를 저장한다. 보류 성분은 진단 트랜잭션의 COMMIT 후 완료로 표시한다. [증분 저장과 실패 테스트](../../../tests/node/memory-incremental.test.ts)

영향 세션 수가 S, 연결 수가 E이면 성분 탐색의 시간은 정렬 O(S log S)와 연결 순회 O(S+E)다. 성분 스캔에서 대기 배열을 제거했다. 최종 파일 순회는 O(F)이며 임시로 모으는 항목은 세션 없는 변경·삭제와 실패 파일뿐이다.

## 저장-03 — 이동 추측에 쓰던 inode 조회와 인덱스 제거

제품의 파일 이동은 파싱된 원본 식별자와 이전 정상 범위의 SHA-256으로 검증한다. 기기·inode로 DB의 이동 후보를 찾던 메소드는 테스트에서만 호출됐다. 인덱스 생성과 조회 API를 제거하고, 기존 DB를 열 때 예전 인덱스를 내린다. 읽기 전후 파일 교체 감지에 쓰는 기기·inode 값과 기존 출처 행은 보존한다. [원본 이동](../../../src/summary/scanner/refresh/relations.ts) · [마이그레이션](../../../src/summary/db/migrations.ts)
