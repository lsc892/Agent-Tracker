# 현재 기능을 유지한 알고리즘 최소화

2026-11-11, Asia/Seoul. 사용자가 서브에이전트로 알고리즘·쿼리·파싱을 다시 검토하고 불필요한 방어·확장 코드를 제거하도록 직접 요청했다. 동작을 보존하는 알고리즘 교체까지 요청 범위로 보고 구현했으며 소스 파일 분리나 영속 구조 확대는 하지 않았다.

## 적용 결과

| 영역 | 제거한 중복 | 실제 반영 |
| --- | --- | --- |
| 부모 계보 | root 확정 후 깊은 계보만 다시 Union-Find·작은 Map 병합 | 확정 root별 직접 그룹화, 같은 Map의 임시 null로 방문 표시 |
| 그룹 통계·이름 | 페이지·전체 개수의 별도 GROUP BY | 같은 집계의 window count 공유, 후속 빈 페이지만 count fallback |
| 도구 순위 | 페이지·전체 개수·비율 분모의 반복 집계 | 같은 그룹 결과에 window 개수·합계·최댓값 계산 |
| 화면 coverage | 사용하지 않는 파일·요청 진단 목록 조회 | 기존 counts SQL만 실행 |
| 요청 저장 | 별도 비용 메타데이터 SELECT·Skill 보존 시 미사용 SELECT·모델 SQL/JS 이중 정렬 | facts·비용 메타데이터 함께 읽기, 사용하지 않는 조회·모델 SQL 정렬 제거 |
| 세션 결제 변경 | 요청 ID 페이지와 요청별 비용 SQL 반복 | 세션 요청·모델의 GROUP BY로 비용 한 번 교체 |
| 삭제 보존 | 같은 세션의 누락 파일마다 같은 요청 SELECT | 세션별 한 번 조회 |
| 제목 추출 | 블록 filter/map·모든 줄 split/map | 블록 한 순회와 첫 유효 줄 반환 |
| 도구 파싱 | 지원 인자 7회 regex 검색·중복 O(n²) 비교 | 인자 한 검색 순회와 입력순 Set 중복 제거 |
| 파일·이벤트 판정 | 비교용 JSON 직렬화·중복 문자열/시각 변환·보장된 범위 검사 | 필드 직접 비교·계산 재사용·실질 경계만 유지 |

SQL 수는 코드에서 확인한 데이터 SELECT/쓰기 호출 수다. rollup 준비나 트랜잭션 SQL은 별도이며 실행 시간 개선율을 뜻하지 않는다.

- 결과가 있는 그룹 통계·이름 페이지: SELECT/GROUP BY 각각 **2→1회**. 빈 첫 페이지도 SELECT 1회이며, 범위를 벗어난 후속 빈 페이지는 기존 count가 필요해 2회다.
- 도구 네 분류의 결과 있는 페이지 또는 빈 첫 페이지: SELECT **8→4회**.
- 화면 coverage: SELECT **3→1회**.
- 기존 요청 저장: 요청마다 별도로 실행하던 비용 metadata SELECT **1회 제거**. Skill 보존 모드에서는 기존 Skill SELECT도 제거한다.
- 세션 결제 변경: 요청별 비용 쓰기 **N→1회**, 요청 ID 페이지 조회 제거.

## 영역별 근거와 통합 경계

- [쿼리 담당 기록](AlgorithmMinimize-queries-2026-11-11.md): raw/rollup·이름·도구 지표와 counts 전용 진입점. [Worker](../../../src/summary/client/worker.ts)와 [DB API](../../../src/summary/db/index.ts) 연결까지 완료했다. 내부 window 필드는 반환 행에서 제거한다.
- [파싱 담당 기록](AlgorithmMinimize-parsing-2026-11-11.md): 제목·Claude/Codex·도구·JSONL·원본 읽기. 이벤트 순서·명시 요청 우선순위·도구 첫 필드 규칙·legacy high-water와 flag 순서를 유지한다.
- [집계 담당 기록](AlgorithmMinimize-aggregation-2026-11-11.md): 계보·파일 판정·이벤트 정규화·중복 진단. 내부 Map 키 순서는 달라질 수 있으나 제품 소비자는 root lookup만 사용하고 root별 원본 배열·winner 순서는 유지한다.
- [저장 담당 기록](AlgorithmMinimize-storage-2026-11-11.md): 비용 조회·Skill 보존·삭제 보존·세션 결제. 쿼리 담당자가 저장 diff를 추가로 읽고 모델 없는 요청·NULL 비용·결제 모드·FK·rollback 의미를 교차 검토했다.

요청별 cursor 페이지의 전체 개수는 cursor 이전을 포함하므로 별도 count를 유지한다. 첫 페이지의 빈 결과 0과 후속 빈 페이지의 전체 개수도 구분한다. 평균 표본·NULL 캐시/시간·미상 모델/시간·비용·필터·정렬·이름 범위·공개 반환 필드는 보존한다. 비용 집계에서 모델이 없는 LEFT JOIN의 NULL행도 기존 `max(1, count(*))`의 최소 1 표본과 같은 의미를 낸다.

손상 JSONL·이미지·부분 줄·Zstd 검증, 파일 교체·재작성, fork/legacy·누락/충돌/순환, 입력 수치 검증, 취소·실패 보존·트랜잭션은 실제 계약이므로 유지했다. winner 차분 집계·COMMIT 묶음·영속 스키마 v19·집계 형식 v2는 유지한다. 새 캐시·테이블·인덱스·dirty mask·자동 임계값은 추가하지 않았다.

## 검증과 한계

전체 소스·호출부·기존 테스트의 계약을 읽고 diff를 검토했다. `npm run typecheck`와 `npm run lint`, `git diff --check`를 통과했다. 초기 정적 검토 뒤 성능·정합성 측정이 명시적으로 요청되어 해당 범위의 실행기와 기존 오류 주입 테스트를 보완하고 실행했다. 전체 자동 suite는 실행하지 않았다.

[후속 A/B 보고서](../../benchmarks/2026-11-11/AlgorithmMinimizeAB-2026-11-11.md)는 현재 1,360·10,000·100요청에서 준비 3쌍·교대 10쌍을 비교한다. 정합성 39쌍과 파싱·계보 900 checks, DB 페이지 10,386대조 및 거래·쿼리 경계 검증을 통과했다. 관련 Node 테스트는 A/B 각 135개 중 134개 통과하고 기존 subagent 기대값 실패 1개가 동일했다.

현재 1건 추가 전체 갱신은 394.270→380.660ms, 10,000건의 비용 포함 일별 표·도구 조회는 31.50%·49.47% 단축됐다. 반면 제공자 세션 평균은 세 규모 모두 5.33–8.24% 느렸고 현재 1건 추가 DB 저장은 3.898→4.687ms로 악화했다. window 함수의 결과 보관·정렬 비용이 남으므로 SQL 횟수 감소를 모든 경로의 속도 개선으로 일반화하지 않는다. 메모리 피크·비공개 실제 로그의 독립 파서 oracle은 미측정이다. 이미 단일 읽기·winner 차분으로 처리하는 핵심 집계는 새 알고리즘으로 불필요하게 교체하지 않았다. 이번 작업에서 보류된 승인 대상은 없다.
