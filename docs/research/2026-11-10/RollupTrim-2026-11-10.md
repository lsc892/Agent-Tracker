# 미사용 rollup 속성 정리

2026-11-10, Asia/Seoul. 기준은 `c9c7ecb`의 제품 코드이며 정리 전 소스·빌드는 별도 A 사본에 보존했다. 사용자는 앞서 확인한 미사용 집계 속성을 정리하고 현재 데이터·10,000요청에서 A/B 각 1회를 측정하도록 승인했다.

## 근거와 적용 범위

- [집계 상태](../../../src/summary/db/rollup-state.ts), [병합 지표](../../../src/summary/db/queries/rollup/metrics.ts), [화면](../../../media/dashboard.js)을 추적했다. 공통 3개 속성은 조회 반환 이후 제품에서 소비하지 않는다. 오류 안내는 원본 facts를 조회하는 별도 진단을 사용한다.
- [세션 시작 시각](../../../src/summary/db/queries/rollup/usage.ts)은 모델 조회에서도 요청 daily의 최소 시각을 사용한다. 제공자 `min_started_at_ms`는 보존한다.
- 상태 수를 provider 41→38, model 41→37로 줄인다. c/r의 완료 표본·빈 사용량 제외 옵션과 NULL 정책, PK·보조 인덱스·트랜잭션 경계는 유지한다.
- 저장 형식과 내부 반환 계약의 제거는 사용자가 구체적으로 승인한 정리 범위다. [마이그레이션](../../../src/summary/db/migrations.ts)은 이전 집계 테이블·메타데이터를 폐기하고 신규 빈 테이블을 생성한다. 원본 facts·manifest·모델·도구·비용·이름은 보존하며 첫 집계 조회에서 재구축한다.
- 입력 요청 N, 일별 집계 행 R에 대한 집계의 시간·공간 차수는 유지된다. 지표 계산·행 폭의 상수 비용 감소를 기대하며 실제 개선량은 메인의 1회 A/B로 판단한다. 일회성 파생캐시 재구축 비용이 생긴다.

## 결과와 검증

- 제공자 38개·모델 37개 상태를 같은 선택 함수로 DDL, 저장용 집계와 부분 날짜 projection에 반영했다. 미사용 3개 속성은 raw/rollup 결과와 `UsageRow`에서도 제거했다.
- 진단 저장은 manifest·요청의 오류 정보를 같은 트랜잭션으로 보존한다. 진단 전용 변경에 입력되지 않는 토큰·시간 집계를 다시 만드는 호출만 제거했다.
- 이전 버전에서는 파생캐시만 비운 뒤 처음 조회할 때 재구축한다. v13 캐시 재사용 테스트는 원본 보존·파생캐시 재구축이라는 새 정책으로 맞췄다. v18 검증은 구 41열 테이블을 구성해 실제 열 제거, facts·manifest·ID·모델·도구·비용 보존, 세션 시작 시각·미상 시각/부분 날짜, 재오픈 캐시 재사용을 확인하도록 보강했다.
- `npm run check`의 타입 검사·린트와 최신 benchmark 린트·`git diff --check`가 통과했다. 기존 경로의 빌드 파일이 모듈을 가리던 문제를 피하도록 양쪽 생성물을 새로 구성한 뒤 기능 테스트 420개 중 414개가 통과했다. 남은 6개는 정리 전 A에서도 동일하게 재현했다. 이번 변경의 v13/v17/v18 전환·평균·NULL·미상 날짜·진단·세션 시작·재오픈 검증은 통과했다.
- 현재 798요청·합성 10,000요청을 각 A/B 1회 비교했다. 최초 rollup은 34.225→34.043ms·269.730→268.088ms로 차이가 작았고 단일 추가 저장은 느려졌다. 두 daily 본체는 112→104KiB·72→60KiB로 감소했다. 반복 표본이 없어 안정적인 속도 개선으로 일반화하지 않는다. [측정·정확성·전환 비용](../../benchmarks/2026-11-10/RollupTrimAB-2026-11-10.md), [의사결정 일지](../../AgentTracker-일지.md).
- 핵심 알고리즘·PK·인덱스·COMMIT 경계와 사용 중인 집계 속성은 유지했다. 추가 승인 대기 후보는 없다.
