# 스트리밍 winner 교체의 로컬 원본 대조

2026-11-08, Asia/Seoul. 사용자가 승인한 집계 알고리즘·구조 교체의 정합성 검증이다.

## 범위와 기준

- 변경 전 실제 집계 결과와 동일한 고정 JSONL 사본을 기준으로 삼는다. 기존 로컬 로그와 설치 DB에는 쓰지 않는다.
- 기준 입력은 601파일(Claude 16, Codex 585)이며 그중 집계 입력 identity가 있는 파일은 600개다. `.jsonl.zst` 464파일을 포함한다.
- 입력 SHA-256은 `092da230cc63f5e0d3fdf5aeddb5ad44d89401e91553ad9f7c7b234e2fb6a798`이다.
- 기준 값은 요청 1,518개, input 2,447,163,487, output 12,661,910, 총 2,459,825,397토큰이다.

## 대조 방법

변경 전 빌드와 기준 DB를 무시되는 `tests/.cache/` 아래에 보존한다. 새 빌드의 [갱신 진입점](../../../src/summary/scanner/index.ts)은 같은 고정 사본을 별도 새 DB에 집계한다.

요청별 제목·시각·상태·토큰·캐시·진단 원본 위치, 모델 벡터, 도구 횟수, 비용, 프로젝트·세션 이름, 원본 처리 상태와 해시를 직접 대조한다. 제공자·모델별 전체·프로젝트·세션·일·월 집계도 비교한다. 자동 생성 DB ID·갱신 시각·scan ID·parser version은 값 보존 대조에서 제외한다.

입력 파일 601개의 SHA-256이 그대로인지 확인하고, 변경 없는 두 번째 갱신은 파싱 0개·본문 읽기 0byte인지 확인한다. 개인 경로·세션 식별자·제목·원시 행은 무시되는 임시 폴더에만 보관하며 이 문서에는 기록하지 않는다.

## 결과

새 [스트림 집계](../../../src/summary/aggregation/memoryAggregate.ts)를 사용하는 실제 갱신을 별도 새 DB에서 실행했다. 기준과 새 구현 모두 요청 **1,518개·2,459,825,397토큰**이며, 요청별 값과 모든 조회 차원에서 차이가 없었다.

파싱 실패는 0개이며, 입력 사본 601개의 SHA-256을 다시 확인해 변경이 없었다. 변경 없는 두 번째 갱신은 파싱 0개·본문 읽기 0byte다. 초회 본문 읽기는 기존 446,954,509byte에서 **893,909,018byte**가 됐다. 첫 순회에서 유효성 근거를 확정하고 두 번째 순회에서 winner만 보유하는 구조에 따른 읽기 증가다. 이 실행은 정합성 확인이며, 반복 시간·메모리 성능 비교는 수행하지 않았다.

기존 요청 1,518개가 있는 v17 DB의 사본을 새 [migration](../../../src/summary/db/migrations.ts)으로 열어 v18로 올린 경우에도 위 7개 저장 값 묶음과 10개 조회 차원이 모두 동일했다. `turn_metadata`와 자식 테이블은 제거됐고, 외래 키 검사와 SQLite 무결성 검사는 통과했다. 설치 DB에는 적용하지 않았다.

## 검토한 경계

두 번째 읽기의 고정 byte 경계·SHA-256 대조와 읽기 실패 시 저장 전 중단을 확인했다. 동점 우선순위에 원래 파일 처리 순서를 유지하고, 패자·제외 후보의 진단 플래그와 사용량만 있던 root의 위치를 보존한다. 복사 접두사 안의 중복 도구 호출과 current가 제외하는 legacy 후보의 request 보정 근거는 별도로 검토해 선택 구현에 반영했다. 실제 대조 외의 합성 반례·타입·린트·전체 회귀 검사는 담당 구현 보고서와 저장소 필수 검사 결과를 따른다. 실계정 quota 호출은 수행하지 않았다.
