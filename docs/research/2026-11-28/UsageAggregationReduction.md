## 알고리즘과 유지 이유

| 구간 | 현재 알고리즘과 필요한 데이터 |
| --- | --- |
| JSONL 파싱과 요청 경계 | 필요한 필드만 읽으며 입력·출력·캐시 읽기·쓰기 네 성분을 최종 응답에 전달한다. Reasoning은 구형 Codex 누계·복사 서명과 토큰 구성 진단에서 사용한다. 시작 시각은 날짜와 세션 정렬, 상태와 소요 시간 품질은 완료 표본과 평균의 분모, 모델·결제는 모델별 표와 추정 비용에 필요하다. 세션·프로젝트 키와 이름은 필터, 요청 키는 저장 중복 검사와 소실 보존에 쓰인다. |
| 파일·세션 중복 제거 | 파일을 읽으면서 같은 키의 응답을 Map에서 찾아 입력·출력 합이 큰 후보를 남긴다. Claude는 메시지·요청 ID, Codex는 스레드·턴·응답 ID를 사용한다. 현행과 구형 기록은 별도로 관리하며 구형 기록은 요청도 구분한다. 세션은 부모 복사 이력을 제외하고 Claude의 누락 요청 ID를 보정한 뒤 식별자로 정렬해 인접한 같은 키를 묶는다. 세션 정렬은 `O(N log N)`, 묶기와 반영은 `O(N)`이다. 앞서 정렬을 전체 키 맵으로 바꾼 실로그 비교에서는 집계 시간과 힙이 늘었다. |
| 누계 검산 | 턴별 최신 검산 항목을 정한 뒤 확정 응답만 해당 항목에 합산한다. 최종 순회에서 검증된 부족분만 보충한다. 0토큰 응답과 응답 부재의 차이, 음수 차분, 뒤늦은 중복 해소를 구별해야 한다. |
| SQLite 일별 저장·조회 | 일별 복합 키로 합계를 묶고 값이 바뀐 행을 UPSERT한다. 별도 키 차집합으로 사라진 행만 지우며, 원본 일부가 소실된 세션에서는 다시 관측한 날짜만 교체한다. 모델별 행을 합치면 여러 모델을 쓴 한 대화가 모델 수만큼 중복되어 제공자 대화 수와 평균이 달라진다. Skill과 원본 상태, 표시 이름과 사용자 결제 설정은 키와 수명이 다르다. 기존 상세 테이블 정의는 이전 DB 이관용이다. |

요청 제목은 여전히 파싱 단계에서 추출한다. 요청별 진단 근거도 수집하며 저장용 요약에서는 진단 문자열과 위치를 만들지 않는다. SQLite 변경은 JS에서 전달하는 필드와 호출 횟수를 줄인 것이며, 일별 테이블 수와 새 DB 파일 크기에는 이번 변경의 절감 수치가 없다. 소실 세션의 교체 범위와 Skill 입력은 현지 날짜를 별도로 계산한다. 날짜를 공유하려면 시간 미상의 빈 날짜 처리와 소실 세션에서 프로젝트에 관계없이 다시 관측한 날만 교체하는 규칙을 함께 보존해야 한다. 턴 누계 검산 대상의 캐시 보정도 대화 합계와 검산 합계에서 각각 계산한다. [교체 범위와 Skill 저장](../../../src/summary/db/rollups.ts) · [턴 누계 합산](../../../src/summary/aggregation/memoryAggregate.ts)

필드, 중복 비교, SQLite를 맡은 서브에이전트 3명이 코드와 호출부를 독립 검토했다. 기존 상세 집계, 첫 등장 위치의 반영 순서, 동점과 BigInt 비교, 모델 NULL과 빈 이름, 명시 결제값 및 소실 보존 조건을 대조했다. 타입 검사, 린트, diff 검사를 수행했다. 자동 테스트와 새 A/B 계측은 실행하지 않았다.
