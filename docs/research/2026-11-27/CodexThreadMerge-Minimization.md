# Codex 스레드 응답 병합의 키 중복 제거

## 기존 흐름

파일별 응답 목록과 토큰 버퍼를 수집기에 넘긴다. 복사본이 들어오면 수집기는 응답 키에서 최종 행 번호를 찾는 `Map`을 만든다. 변경 전에는 대표 원본의 응답이 동점에서 이기는지 판단할 때 같은 문자열 키를 `Set`에서도 조회했다. 대표 원본이 교체될 때에는 이 집합을 새로 만들었다. [갱신 상태 등록](../../../src/summary/scanner/refresh/state.ts#L125) · [Codex 응답 병합](../../../src/summary/scanner/refresh/aggregation.ts#L173)

## 적용

사용자가 요청한 스레드별 `Map`과 응답 배열 경로 단순화의 범위 안에서 기존 병합 함수를 수정했다. 각 응답 행의 winner가 참조하는 원본 순서 객체를 행 번호와 같은 위치에 둔다. 동점에서는 기존 winner의 원본 참조와 현재 대표 원본의 참조를 비교한다. 대표가 바뀌면 새 참조를 기준으로 비교한다. 파일이 하나인 경우에는 응답 배열과 토큰 버퍼를 인수한다.

## 검증

- 기존 대표가 유지될 때 동점 복사본은 동일 행의 기존 winner가 대표에서 유래했는지 확인한다. 새 대표가 들어오면 기존 winner와 동점인 행을 채택한다. 고득점 복사본이 기존 대표의 행을 교체하면 이후 비대표 동점 후보는 기존과 같이 나중 순서가 우선한다.
- 첫 파일의 응답에 배열 행 번호가 유지되고, 첫 파일에 응답이 없더라도 새 행이 0부터 추가되는 흐름을 확인했다. 후보가 패배해도 누계 검산에 쓰는 행 번호는 승패 비교 전에 채운다. SQLite 입력은 같은 응답·토큰 배열에서 나온 스레드별 합계를 사용한다. [누계 검산](../../../src/summary/aggregation/threadAccounting.ts#L138) · [SQLite 입력](../../../src/summary/db/dailyFacts.ts#L15)
- 코드·참조와 diff를 검토했다. 자동 테스트와 메모리 실측은 수행하지 않았다.
