# 원본별 winner 영속 저장 A/B 테스트

2026-11-23, Asia/Seoul. 사용자는 파싱하면서 원본별 winner를 고르고 기존 SQLite 후보와의 비교를 최종 단계에 모으도록 요청했다. 변경되지 않은 관련 원본의 파싱을 줄이면 실제 갱신이 빨라지고, 빈 DB의 첫 수집에는 후보 저장 비용이 추가될 것으로 예상했다.

- **A**는 `[Docs] JSONL 선택 파싱 재실험 결과 추가` 커밋 `bd5364aeba1c4d1e2527c04862c31a9676a2f82f`다.
- **B**는 `f386eb0c3eb25d3418e9d6a42c5a071a40214f85`를 바탕으로 원본별 winner를 영속 저장하는 작업 트리다. 변경 원본에서 파싱한 후보는 메모리에서 직접 사용한다. 기존 관련 원본의 비교값은 묶어서 읽고, 이 가운데 최종 승자의 토큰·모델·결제만 조회한다.

## 3. 확인한 손익

- 실제 1건 추가는 B가 20쌍 모두 빨랐다. 파싱 파일 수가 4→1개, 본문 읽기가 27,140,525→16,160,125바이트(−40.46%)로 줄어 원본 읽기·파싱 단계가 275.18→112.14ms로 단축됐다. 최종 집계는 1.89→4.03ms로 늘었지만, 관련 로그 본문을 건너뛴 효과가 더 컸다. 피크 RSS도 20쌍 모두 줄었다. 피크 힙은 중앙값이 낮았고, B가 낮았던 표본은 9/20쌍이었다. [관련 원본 재사용](../../../src/summary/scanner/refresh/preparation.ts)
- 두 합성 입력은 세션마다 원본이 한 개다. 두 빌드 모두 1건 추가에서 같은 1개 파일과 같은 바이트를 읽었다. 시간 중앙값은 약 1% 늘었고 사분위 범위는 겹쳤다. 네 평균 토큰 조회의 중앙값 차이는 모든 입력에서 0.11ms 이내였다.
- 빈 DB의 실제 재수집은 두 빌드가 같은 418파일을 읽었다. 최종 집계는 107.05→82.24ms로 단축됐고, 후보까지 쓰는 원본 저장 구간은 10.24→118.62ms로 늘었다. 전체 재수집 시간은 실제 입력에서 사분위 범위가 겹쳤다. 합성 10,000요청은 20쌍 모두 전체 재수집이 느려졌고, 피크 힙은 19쌍에서 늘었다. 재사용할 이전 원본이 없는 첫 수집에서는 영속 저장 비용이 남는다.
- 별도 실측 1회에서 실제 922요청의 v21 사본을 v22로 여는 데 5.90ms, 후보를 처음 채우는 갱신에 4,333.94ms가 들었다. 이관 직후와 첫 스캔 완료 뒤 모두 v21의 요청·모델·도구·비용 행 해시가 일치했다. 다음 무변경 갱신의 본문 읽기는 0바이트였다.

## 4. 측정과 정합성

- Windows x64, Intel Core i5-8250U, Node 24.19.0, SQLite 3.53.3에서 빌드별 독립 프로세스와 최대 4개 파일 Worker를 사용했다. 각 작업·입력에서 준비 3쌍을 거쳐 A→B와 B→A를 각각 10쌍씩 실행했다. 이전 실험과 같은 고정 사본을 사용하고 양쪽을 다시 측정했다. OS 파일 캐시는 유지했다. 타이머는 `refreshSummary` 호출부터 COMMIT과 갱신 종료까지이며, 미리보기는 사용하지 않았다. 추가 텍스트 쓰기·원복·빈 DB 스키마 생성·강제 GC·검증은 타이머 밖에서 수행했다.
- 실제 사본은 일반 JSONL 418개, 616,959,493바이트, 922요청과 1,849,943,425토큰이다. 1건 추가에는 16,159,523바이트의 일반 Codex 메인 로그 사본을 사용했다. 합성은 고정 산식으로 10개 프로젝트와 최대 14일에 Claude·Codex를 절반씩 배치했다. 10,000요청은 100세션·세션당 100건, 100요청은 10세션·세션당 10건이다. 초기 토큰 합계는 각각 6,340,000개와 18,400개다.
- 저장 직후 `queryUsagePage`로 일·월·세션·프로젝트별 결과의 모든 페이지를 가져왔다. 기간은 2020-01-01 UTC 이상, 2035-01-01 UTC 미만이며 시각 미상 요청을 포함했다. 일·월 경계는 Asia/Seoul이며 평균의 분모는 빈 완료 요청을 포함한 모든 완료 요청이다.
- 준비를 포함한 207쌍에서 요청 수·토큰 합계와 요청·모델·도구·비용 행 해시가 일치했다. 추가분은 모두 1요청·130토큰이며, 합성 초기 합계는 생성기의 기대값과 같았다. 무변경과 추가 갱신 뒤의 조회 1,104건을 정규화된 요청에서 독립 계산한 그룹 수·토큰 합계·평균과 대조했다. 반복 완료 뒤 모든 입력 사본의 파일 해시를 확인했다. [원시 표본·입력 및 빌드 해시](PersistentWinnerRefreshAB-2026-11-23.json)
