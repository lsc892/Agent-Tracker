# DTO greedy A/B 테스트

2026-11-08, Asia/Seoul. 측정 15:02:57~15:06:09. 제품 기준은 `3b99d1a`이며 제품 소스·설치 DB·원본 로그는 변경하지 않았다.

가정: 사용자는 파일을 순회하면서 패자를 버리고 기존 DTO를 갱신하면 winner Map과 GC 비용을 줄일 수 있다고 제안했다. 검사 전 패자 폐기, 캐시의 원본 DTO 직접 덮어쓰기, 검사 후 winner 슬롯 재사용을 구분해 검증했다.

**사용자 설명에 따른 범위 정정:** 요청한 방식은 파일을 읽는 한 번의 집계에서 winner DTO를 갱신하고 패자를 버리는 것이다. 아래 실험 중 다음 갱신의 캐시 재사용·승자 파일 삭제·세션 이동은 에이전트가 추가한 조건이다. 이 결과를 한 번의 순회 방식이 실패한다는 근거로 사용한 기존 결론을 정정한다. 삭제 실험은 집계 도중 파일이 사라지는 상황을 재현한 것도 아니다.

실제 측정 대상: **A = 현재 기본 메모리 집계**, **B = 귀속·유효성 검사·Claude request 보정·원본 캐시는 유지하되 winner Map을 배열 선형 탐색으로 바꾸고 승자 교체 때 기존 슬롯 필드를 갱신하는 대조군**이다. B는 별도 사본의 집계 모듈에만 적용했다. 배열 선형 탐색은 에이전트가 선택한 구현이다. 아래 시간·heap 수치는 B의 결과이며, 파일 읽기와 DTO 생성부터 통합한 스트리밍 구현의 성능이나 GC 절감 효과는 측정하지 않았다.

### 한 번의 순회에 대해 확인한 내용

중복 그룹과 후보의 유효성이 정해져 있으면, 각 그룹의 winner DTO 하나만 유지하며 새 후보의 input+output이 더 크거나 동점에서 더 늦으면 교체하는 방식은 기존 max 선택과 같다. 이 선택 과정에서 탈락한 토큰 벡터 전체를 보관할 필요는 없다. 이번 B와 고정 입력 테스트에서도 이 선택 결과는 일치했다.

삭제 사례는 첫 집계가 끝난 뒤 다른 입력으로 두 번째 집계를 수행한 것이다. 매 집계에서 파일을 새로 읽어 winner를 구성한다면 삭제된 파일의 과거 패자를 재사용해야 한다는 전제가 없으므로, 해당 사례를 요청한 방식의 정합성 실패로 제시할 수 없다.

파일을 읽는 즉시 귀속·legacy/current 제외·복사 접두사·Claude request 보정까지 처리하는 전체 구현은 이번 실험에 없다. 위의 유효성 검사 전 폐기 테스트는 이 선행 조건을 생략했을 때의 한계를 보여준다. 선행 조건을 처리하면서 winner DTO만 유지하는 모든 구현이 실패한다는 증거는 아니다.

실제 고정 사본은 **600파일·444,752,985 bytes**, 정상화 요청 **1,514개·2,455,634,711토큰**이었다. 파싱 실패는 A/B 모두 0개다. 집계 입력에는 identity가 있는 599파일의 DTO 45,990개, usage DTO 25,369개가 있었다.

실제 데이터에서 검사 전 max 선택 후 기존 유효성 검사를 적용한 통제는 요청별 결과까지 일치했다. 이는 반례를 부정하지 않는다. 이 사본에서 최종 유효한 작은 패자가 가려지는 조합이 관측되지 않은 것이다. 이전 실험의 필터 생략 후보와도 다르다. 이번 조기 선택 후보는 원래의 current/legacy·복사 접두사 제외를 선택 **후에** 실행하며, 최종 세션까지 미리 제공받는다.

별도 캐시 재사용 실험에서는 검사 완료 후 모든 usage 중 winner만 남기고 나머지 비사용량 이벤트를 그대로 캐시한 뒤 다시 집계하면 토큰은 같지만 요청 수가 **1,514 → 1,564**로 달라졌다. 추가된 50개는 모두 0토큰 요청이고 기존 1,514개 행은 같았다. 복사 usage를 버리면 다음 갱신에서 그 복사 접두사의 root를 제외할 근거도 사라지기 때문이다. 이 수치는 축약한 원본 캐시의 재사용 문제이며, 한 번의 파일 순회 결과가 틀렸다는 뜻은 아니다.

## 3. 공간·GC·시간 복잡도

U는 유효한 usage 후보 수, G는 중복 그룹 수, E는 원본 캐시의 전체 DTO 수다. 식별자 길이와 해시 조회 비용을 상수로 보는 선택 단계의 분석이다.

| 항목 | A: winner Map | B: 배열 선형 탐색·슬롯 갱신 |
| --- | --- | --- |
| 선택 시간 | 평균 해시 조회 가정에서 O(U) | O(U×G), G≈U이면 O(U²) |
| 선택용 추가 공간 | O(G) | O(G) |
| 원본 파일 캐시 | O(E) | O(E) |
| winner 슬롯 객체 생성 | 새 그룹 + 승자 교체마다 | 새 그룹마다 |

이는 이번 B의 winner 선택 단계에 대한 분석이다. 공통 계보·legacy 비교·root/도구 집계·정렬·저장까지 전체 갱신을 O(U)라고 주장하지 않는다. 실제 파일 순서에는 같은 그룹의 이벤트가 인접한다는 보장이 없어 배열의 마지막 DTO만 검사할 수도 없다. DTO 저장소 자체에 그룹별 조회 인덱스가 있으면 별도 winner Map 없이도 빠르게 winner를 찾을 수 있다. 따라서 위 O(U×G)는 배열 `.find`를 선택한 B의 비용이며, DTO 직접 갱신 방식 자체의 필연적인 시간 복잡도는 아니다.

시간 표본과 분리한 연산 계측 결과:

| 입력 | A Map 조회 | B 그룹 비교 | A winner 객체 생성 | B winner 객체 생성 |
| --- | ---: | ---: | ---: | ---: |
| 실제 | 22,751 | **254,953,724** | 22,751 | 22,581 |
| 10,000요청 | 10,000 | **49,995,000** | 10,000 | 10,000 |
| 100요청 | 100 | 4,950 | 100 | 100 |

이번 B에서 슬롯을 재사용해 줄인 객체는 **170개(0.75%)**였다. B는 원본 usage DTO를 별도 파일 캐시에 계속 보존하므로 이 실험에서는 해당 DTO가 GC되지 않는다. 파일을 읽으면서 패자를 보관하지 않는 구현의 원본 DTO 메모리 절감량은 이 수치로 평가할 수 없다.

별도 프로세스에서 입력을 먼저 로드하고 강제 GC 뒤 선택 종료·함수 반환 시점의 heap을 관측했다. 각 3회 준비 후 10회 표본의 추가 heap 중앙값이다. **연속 peak나 전체 확장 메모리가 아니며**, 공통 원본 캐시의 메모리는 시작값에 포함되어 차이에서 제외된다.

| 선택·집계 중 추가 heap | A MiB | B MiB |
| --- | ---: | ---: |
| 실제 | 57.11 | 58.06 |
| 10,000요청 | 53.56 | 53.00 |
| 100요청 | 1.29 | 1.27 |

B에서는 일관된 메모리 감소를 관측하지 못했고 공간 차수도 개선되지 않았다. **파일 읽기부터 통합한 스트리밍 후보의 시간·공간, GC 횟수·pause 시간·연속 최대 RSS는 미측정**이다. 객체 생성 수만으로 GC 시간 개선을 추정하지 않는다.

## 4. 검증·선택·재실행

- 배열 선형 탐색인 B는 전체 집계를 크게 악화시켜 채택하지 않는다. 다만 다음 갱신의 캐시 재사용 반례로 사용자가 설명한 한 번의 순회 방식을 기각한 결론은 철회한다. 선행 조건이 확정된 그룹별 greedy max 선택은 일치했고, 파일 읽기부터 통합한 전체 스트리밍 후보의 정합성과 성능은 별도 구현·검증이 필요하다. 제품 코드는 유지했다.
