# 스트리밍 winner A/B 테스트

2026-11-08 17:39:09–2026-11-08 17:46:55, Asia/Seoul.

가정: 사용자는 파일을 읽으며 같은 그룹의 winner와 비교하고 더 좋은 후보의 전체 값을 같은 DTO에 반영한 뒤 패자를 버리는 방식을 요청했다. 에이전트의 성능 가정은 전체 이벤트 DTO 보관을 줄이면 메모리를 절약할 수 있으나 유효성 근거와 winner 선택을 위한 두 번의 읽기로 수집 시간은 증가할 수 있다는 것이다.

개선 방향: A = 교체 직전 보존 빌드의 파일별 전체 DTO 캐시·후처리 winner 선택. B = 현재 작업 트리의 근거 수집 → 두 번째 읽기에서 winner DTO 갱신·패자 폐기. B는 그룹 조회용 Map을 유지한다. 이전 배열 선형 탐색 대조군과 다른 실제 수집 구현이다. 제품 코드와 설치 상태는 이번 실험에서 바꾸지 않았다.

## 2. 분석

- **판정: 일부 성립.** 현재 사본의 수집 후 보유 heap은 줄었지만 초회 수집은 **1.82배**, 한 건 추가는 **4.11배** 느려졌다. 현재 추가 A 범위 242.27–249.49ms와 B 993.08–1071.61ms는 겹치지 않는다. 1만 요청에서는 초회 수집 **30.26%**, 추가 **10.21%** 개선이며 측정 10쌍 모두 B가 빨랐다. 100요청은 추가 차이가 0.27ms이고 범위가 겹쳐 개선으로 보지 않는다.
- **핵심 원인: 읽기와 저장의 비중이 다르다.** 현재 사본은 초회 446.95 → 893.91MB로 두 번 읽는다. 추가는 기존 변경 파일의 18.94MB만 읽던 경로에서 관련 원본도 재파싱하는 133.03MB로 늘었다. 별도 진단에서 추가의 읽기·파싱 시간은 126.36 → 882.16ms, 파싱 파일은 1 → 27개였다. 해당 진단의 저장 시간은 7.02 → 2.88ms로 줄어, 읽기 증가가 저장 절약을 압도했다.
- **1만 요청의 개선은 winner 선택 하나의 효과가 아니다.** 입력은 5.64MB로 작고 요청 수가 많다. 별도 진단에서 초회 읽기·파싱은 113.49 → 282.09ms로 늘었지만 저장은 842.62 → 336.08ms로 줄었다. A는 `turn_metadata` 10,000행과 모델·도구 자식 행을 저장하고, B는 이 테이블을 제거한다. 저장량 축소가 추가 읽기 비용보다 컸다. 이 비교에는 스트리밍 수집·원본 캐시 제거·파생 metadata 저장 제거가 함께 포함된다.
- **조회·변경 없는 갱신:** 네 평균 조회의 범위는 모두 겹치고, 조회 구현 JS 12개 파일의 hash가 A/B 동일하다. 조회 속도 개선을 주장하지 않는다. 변경 없는 갱신은 두 방식 모두 본문 0byte이고 시간 차이도 변동 범위 안이다.
- **선택: 메모리 보관량 감소는 확인, 전반적인 속도 개선 주장은 보류.** 현재처럼 큰 관련 원본이 있는 입력에서는 속도 비용이 명확하다. 이번 요청은 A/B 비교이므로 현재 제품 구현을 채택·철회하거나 설치 상태를 바꾸지 않았다.

### 메모리와 측정 한계

단위는 MB(1,000,000byte), 각 값은 초회 수집 완료 시 10표본의 중앙값이다.

| 측정 항목 | 현재 1,518건 | 10,000건 | 100건 |
| --- | ---: | ---: | ---: |
| 수집 후 강제 GC의 보유 heap A → B | 25.09 → 8.38 | 15.09 → 7.41 | 7.08 → 6.97 |
| 초회 완료 시 프로세스 high-water RSS A → B | 249.48 → 276.18 | 150.63 → 157.31 | 56.62 → 56.07 |

현재 사본의 보유 heap은 **66.61% 감소**했지만 high-water RSS는 **10.70% 증가**했다. 보유 heap 감소를 최대 메모리나 GC 정지 시간 감소로 해석하지 않는다. GC 정지 시간·연속 heap peak·OS 캐시가 cold인 조건·v17→v18 마이그레이션은 이번 A/B에서 **미측정**이다. 초회 구축 비용은 위 표에서 별도로 반복 측정했다. 추가는 가장 요청이 많은 정상 Codex 원본 한 곳을 대상으로 하므로 모든 파일 크기·제공자의 대표값은 아니다.

읽기 시간은 파서 callback과 B의 winner 갱신을 포함한다. A의 전체 집계 함수와 B의 `finish()`는 포함 범위가 달라 독립 선택 커널 성능으로 비교하지 않는다. 진단 수치는 각 variant·규모 한 번의 별도 계측이며 본 A/B 중앙값에 섞지 않았다. [진단·재실행·검증 JSON](StreamingWinnerVerification-2026-11-08.json)에 원시 구간과 실행 명령을 보존한다.
