# 통계 갱신 A/B 요약

측정: 2026-11-03, Asia/Seoul. **음수는 감소, 양수는 증가**다. 변경 전·후 중앙값과 증감률을 비교한다.

## 재파싱 쿼리 개선 — 코드 반영

세션마다 임시 집계 표·인덱스를 다시 만들던 처리를, **표·인덱스를 유지하며 내용만 교체**하도록 바꿨다.

**실제 로그의 재파싱 대기: 15.342초 → 13.610초, 1.732초 단축(-11.3%).** 집계 준비는 **-59.3%**이며 3회 모두 대기가 줄었다.

| 입력 | 재파싱 대기(초): 전 → 후 | 증감률 | 집계 준비(초): 전 → 후 | 증감률 |
| --- | --- | --- | --- | --- |
| 실제 1,363요청 | 15.342 → 13.610 | -11.3% | 2.393 → 0.973 | -59.3% |
| 1만·100요청/세션 | 2.994 → 2.737 | -8.6% | 0.704 → 0.400 | -43.2% |
| 1만·1,000요청/세션 | 1.635 → 1.635 | +0.0% | 0.294 → 0.270 | -8.3% |

예열 제외 3쌍. 대기는 재파싱부터 첫 통계 페이지 반환까지다. 집계 준비는 대기 시간에 포함되므로 더하지 않는다. 실제 입력은 1,363요청이다.

## 세션 시간 인덱스 1개 추가 — 실험 결과

추가한 인덱스는 `(provider, session_id, started_at_ms)`이며 SQL은 같은 조건이다. 위의 재파싱 쿼리 개선과 별도로 비교했다.

| 항목 | 실제 1,360요청 | 1만·100요청/세션 | 1만·1,000요청/세션 |
| --- | --- | --- | --- |
| Codex 요청 +1 갱신 증감 | -3.355ms (-1.2%) | -0.434ms (-0.7%) | +5.933ms (+3.0%) |
| Claude 요청 +1 갱신 증감 | +0.918ms (+0.6%) | +2.865ms (+5.1%) | +3.735ms (+1.9%) |
| Codex 요청 +1 트랜잭션 증감 | -0.042ms (-0.2%) | -1.473ms (-6.2%) | +4.150ms (+3.5%) |
| Claude 요청 +1 트랜잭션 증감 | -0.428ms (-1.8%) | +1.423ms (+6.3%) | +1.690ms (+1.4%) |
| 기존 DB에 인덱스 생성 시 추가량 | +80KiB (+3.7%) | +424KiB (+8.7%) | +424KiB (+8.9%) |
| 최초 생성+COMMIT | 1.618ms | 5.145ms | 4.955ms |

예열 제외 5쌍. 갱신·트랜잭션 증감은 B 중앙값 − A 중앙값이다. 트랜잭션은 갱신 중 쓰기 트랜잭션의 누적 시간이며 갱신 전체에 포함된다. DB 추가량·생성 시간은 기존 데이터에 인덱스를 처음 만들 때의 값이다. 처음부터 인덱스를 유지한 적재의 DB 증가량은 실제 **88KiB**, 두 합성 입력은 각각 **476KiB**였다.

인덱스만 추가한 실제 전체 재파싱은 **-2.8%**였지만 5회 중 빨라진 것은 2회였다. 일관된 개선으로 채택하지 않았으며, 작은 시간 차이는 반복 편차를 포함한다. 이 실험의 실제 입력은 1,360요청으로 위 재파싱 실험과 다른 snapshot이다.
