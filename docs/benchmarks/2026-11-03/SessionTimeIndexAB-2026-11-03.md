# 세션 시간 인덱스 하나의 갱신·공간·트랜잭션 A/B

기준일: 2026-11-03, Asia/Seoul.

실제 **1,360요청·438세션**에서는 요청 1개 추가 시 세션 저장 호출의 중앙값 차이가 **Codex +0.147ms, Claude +0.183ms**였다. 갱신 전체는 각각 **-3.355ms·+0.918ms**, 쓰기 트랜잭션 누적은 **-0.042ms·-0.428ms**로 관측됐다. 현재 입력에서 큰 증분 갱신 부담은 관측하지 못했지만 회차 편차보다 작은 차이를 고정 비용으로 단정하지 않는다.

합성 **1만 요청·1,000요청/세션**의 요청 추가 갱신은 **+3.735~5.933ms**, 쓰기 트랜잭션 누적은 **+1.690~4.150ms** 늘었다. 두 제공자 모두 5회 중 4회에서 B의 갱신이 느렸다. 이 규모에서는 소폭의 추가 비용을 예상할 근거가 있다. 공간은 기존 DB에 처음 만들 때 실제 **+80KiB**, 합성 1만 요청 **+424KiB**이며, 처음부터 인덱스를 유지한 최초 적재는 각각 **+88KiB·+476KiB**였다.

## A/B 조건

A는 현재 제품 그대로, B는 아래 인덱스 **하나만** 추가했다. [이전 후보 비교](SimpleIndexAB-2026-11-03.md)의 B에 해당한다. 이전 E에 있던 세션 최초 시각 SQL 조정은 적용하지 않았다. 제품 소스·스키마 버전·설치 DB는 변경하지 않았다.

```sql
CREATE INDEX bench_summary_session_time
ON turn_summary(provider, session_id, started_at_ms);
```

같은 빌드를 별도 프로세스에서 실행하고, 각 A/B 실행마다 새 DB를 만든다. 각 입력의 로그를 한 번 고정한 뒤 모든 실행에서 같은 사본을 사용한다. 예열 1쌍을 제외하고 **5쌍**을 측정하며 AB/BA 순서를 교대했다. 양쪽 모두 같은 제품 optimize와 계측을 사용하고 기존 PK·인덱스는 유지한다. 실행 전후 소스·컴파일 파일·실행기·로그 사본 해시를 확인했다.

## DB 추가량과 최초 생성 비용

다음은 최초 수집과 첫 집계 조회를 마친 뒤의 값이다. WAL을 TRUNCATE checkpoint한 메인 DB 파일 크기를 사용하고 VACUUM은 실행하지 않았다. 추가 인덱스의 페이지 할당량은 `dbstat`으로 따로 기록했다. 기존 free page 재사용과 다른 객체의 페이지 배치 때문에 파일 증가량과 인덱스 자체 크기가 다를 수 있다.

## 정확성·해석 범위

- 각 상태에서 제공자/모델 × 전체/프로젝트/세션/일/월의 10가지 집계를 원본 SQL 전체 결과 및 전체 그룹 수와 대조했다.
- 요청·모델·Skill·비용·이름·파일 진단의 의미 해시와 집계 해시, 요청/토큰 수·파싱/실패 수·읽기량·저장 호출 수·트랜잭션 수를 A/B 간 대조했다. 같은 상태의 해시는 반복 회차 간에도 일치해야 한다.
- FK 및 `integrity_check`를 모든 상태에서 수행한다. 물리 ID·갱신 시각 등은 의미 해시에서 제외하고 비정수 비교만 유효숫자 10자리로 정규화한다. 저장 값은 바꾸지 않는다.
- 개인 본문·제목·세션 ID·원본 경로는 보고서에 기록하지 않는다. 실제 입력의 진단 오류가 있다면 양쪽에 같은 오류 수와 의미 해시가 나와야 하며, 수는 JSON에 남긴다.
- 한 장비에서 OS 파일 캐시를 비우지 않은 반복 실행이다. 관측 차이는 인덱스의 유지·검색 효과와 실행 편차를 함께 포함하며, 작은 차이로 항상 느려지거나 빨라진다고 단정하지 않는다. 계측 콜백은 양쪽에 동일하게 적용했지만 약간의 추가 비용이 있다.
- 월별 첫 100행과 COUNT 조회는 갱신 타이머 이후에 따로 측정했다. 최초 조회에는 일별 집계의 초기 구축이 포함되며 `firstPageMs`와 `refreshAndPageMs`를 JSON에 보존했다.

측정 표본 **180개 상태**와 기존 데이터 인덱스 생성 15회에서 검증을 통과했다. 위 수치에서 제외한 예열 36개 상태도 같은 검증을 통과했다. 측정 상태와 생성 후의 원본/집계 대조는 총 **1950회**이며, 모든 A/B·회차의 의미 해시·집계 해시·FK·무결성·로그 사본 복원·소스 해시 검증을 통과했다. `npm.cmd run check`의 타입 검사·린트·**374개 테스트**도 통과했다.
