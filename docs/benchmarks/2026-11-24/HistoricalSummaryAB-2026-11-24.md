# 최근 30일 통계 A/B 커밋과 v0.3.1 대비 시간·공간 비교

비교 기준은 `9627303` [Docs] 최근 30일 통계 첫 화면 A/B 결과 추가, `fd83620` [Release] v0.3.1, 그리고 `c4aa914` 위 미커밋 변경을 포함한 현재 작업 트리다. 두 과거 커밋은 `fdbc6af`에서 갈라졌다. 각 커밋 자체를 컴파일해서 비교했다. 현재는 선택 파싱, 응답별 최고값의 즉시 병합, 스레드 단위 집계와 일별 전용 SQLite가 함께 적용된 상태다. 각 변경만의 인과 효과는 이 실험에서 분리하지 않았다.

선택 파싱과 즉시 병합은 파싱·최종 집계의 임시 할당을 줄이고, 일별 전용 스키마는 상세 행과 인덱스 쓰기를 줄일 것으로 예상했다. 이미 일별 집계를 갖춘 조회는 과거 두 기준도 동일한 종류의 사전 집계를 사용하므로, 집계 행 수가 적게 줄면 단축 폭도 작을 것으로 예상했다.

로컬에서 사라진 상세 행은 요청 1,585개, 모델 1,549개, 비용 1,585개다. 저장된 원본 행은 세 빌드에서 712개였고 요청 일별 행은 437 → 404, 모델 일별 행은 462 → 408이었다. 합성 1만 건에서 세 빌드의 일별 사용량 행은 100개, 일별 모델 행은 200개로 같았다. 이전 두 빌드에서는 요청·모델·비용 상세가 각 1만 행 더 있었다.

기존 로컬 DB를 이관할 때 파일 자체는 각각 2.164 MiB와 2.227 MiB를 유지했다. 재사용할 수 있는 페이지가 224개와 227개 생겨 사용 중인 공간은 1.289 MiB와 1.340 MiB로 줄었다. 사본에 진단용 `VACUUM`을 실행한 뒤에는 양쪽 모두 1.129 MiB였다. 이관 직후 토큰·표본 집계는 기존 값과 일치했다.

로컬 두 기준은 1,585요청·3,302,944,678토큰, 현재는 693스레드·3,552,977,688토큰을 집계했다. 현재의 제공자별 입력·출력·합계는 독립 JSONL 검산과 일치했다. 차이 250,033,010토큰은 Codex에서 발생했다. 같은 입력 한 건을 추가하면 세 빌드 모두 130토큰이 늘었고, 두 기준은 요청 표본이 한 건 늘었다. 현재는 기존 스레드에 합산되어 스레드 표본이 유지됐다.

합성 입력은 세 빌드 모두 원본에서 계산한 토큰 합계와 일치했다. 집계 표본 수는 각각 10,000 → 100, 100 → 10이었다. 준비 실행을 포함한 429회에서 추가 전후의 토큰·표본 수와 같은 빌드의 조회 그룹 해시가 확인됐다. 두 기준의 그룹 해시는 일치했다. 이전 빌드의 조회는 상세 행, 현재의 조회는 일별 행에서 JS로 따로 합산해 그룹별 평균을 검산했다. 모든 수집 DB는 SQLite 무결성과 외래 키 검사를 통과했다.

## 알고리즘별 시간·공간복잡도

`F`는 탐색한 디렉터리 항목과 저장된 원본 행의 수, `B`는 실제 디스크 읽기 바이트, `Z`는 압축 해제 후 JSONL 바이트, `L`은 파서가 보유하는 최대 행 길이다. `W`는 영향 범위의 파일별 winner 개수 합, `U`는 병합 뒤 고유 winner 수, `E`는 누계·관계 등 추가 근거, `R`은 요청 상세 및 자식 상세 행, `S`는 스레드 결과와 그 모델 표본, `D`는 영속 일별 행, `G`는 조회 결과 그룹 수다. 집계 키 길이와 Worker 수는 고정으로 보고 Map 연산은 평균 상수로 계산했다.

| 알고리즘 | 두 기준 커밋 | 현재 |
| --- | --- | --- |
| 파일 발견·무변경 판정 | 일반적인 고정 루트 탐색은 시간·공간 `O(F)`. [Docs]는 전역 이전 스캔 시작 시각, 릴리스는 파일의 크기·mtime·inode 등과 저장 상태를 사용한다. | 시간·공간 `O(F)`. 파일별 저장 mtime 및 처리 상태를 좁은 열로 순회하고 무변경에서는 세션 관계 색인을 생략한다. |
| JSONL·해시 | 청크의 완료 행들을 디코딩한 뒤 전체 JSON 객체를 생성한다. 읽기·SHA-256·해제·파싱 시간 `O(B + Z)`, Worker당 임시 공간 `O(C + L)`이며 `C`는 디코더 청크 크기다. | 시간 `O(B + Z)`, Worker당 공간 `O(C + L)`. 행별 디코딩과 지정 필드 추출로 한꺼번에 만들 문자열·객체를 줄이고 원본 SHA-256 패스를 제거했다. 행 경계와 선택 필드는 계속 확인한다. |
| 부모 관계 | 미확인 참조 `H`개를 Codex 경로 `F_c`개와 대조하는 데 최악 `O(F_c H)` 비교가 든다. 부모 요청과 원본 이동 해시 검사도 수행한다. | 저장된 Thread ID를 한 번 색인할 때 시간·공간 `O(F_c)`. 이후 평균 `O(H + K)`로 조회하며 `K`는 동일 ID 후보와 누적 재탐색에서 순회한 항목이다. 부모 누계 비교와 배치 정렬은 별도다. |
| 최고값 병합·집계 | 준비한 파일 개수 `F_a`에 대한 정렬 상한 `O(F_a log(1+F_a))`와 후보·근거 순회가 있다. 파일별 winner와 최종 Map, 요청 DTO를 함께 보유하여 보조 공간은 `O(W + U + E + R)`다. | 읽기 결과가 도착할 때 파일별 winner를 스레드 맵에 합친다. 병합·집계의 대표 비용은 기대 `O(W + E + S)`. 보조 공간은 `O(U + E + S + W_{pool})`이며 `W_{pool}`은 작업 중인 파일과 제한된 앞보기 결과다. 복제본 교체에 필요한 키 복사와 fork별 공유 prefix 비교는 별도다. |
| 요청 1건 추가 | 디렉터리를 탐색한 뒤 영향 파일의 본문을 읽고 요청 상세를 대조·갱신한다. 초기화된 일별 행은 영향 세션 범위에서 다시 계산한다. | `O(F)` 탐색과 영향 파일 전체 읽기가 유지된다. 그 범위에서 스레드를 집계해 일별 행을 갱신한다. 삽입된 입력 요청이 기존 스레드에 속하면 스레드 집계 샘플은 그대로다. |
| SQLite 영속 쓰기 | 변경 시 요청·모델·비용 상세와 인덱스를 유지하고, 준비된 일별 집계를 함께 갱신한다. 영속 공간 `O(F + R + D)`. | 스레드·모델 사실 `S_a`를 배치 JSON으로 만들어 SQL에 전달하는 추가 공간 `O(S_a)`를 쓰고, 일별 키의 바뀐 값과 사라진 행을 반영한다. 영속 공간 `O(F + D)`. 두 쪽 모두 SQLite 인덱스 검색·삽입에 B-tree 비용이 든다. |
| 일별·월별·세션별·프로젝트별 조회 | 일별 집계가 준비됐으면 범위 내 일별 행 `Q`개를 그룹화한다. 비용 등 원시 경로에서는 `Q`가 범위 내 상세 행 수다. | 같은 그룹 연산을 일별 행에서 수행한다. SQLite가 그룹과 출력 정렬에 임시 B-tree를 쓰는 경우 페이지당 시간 상한은 양쪽 모두 `O(Q log(1+Q) + G log(1+G))`, 보조 공간은 `O(Q + G)`. 현재의 차이는 주로 `Q`와 `G`다. |
| 최근 30일 미리보기 | [Docs]는 원본 메타데이터와 최근 요청 상세 및 자식 행을 임시 DB로 복사한다. 복사하는 행 수 기준 공간 `O(F + R_{30})`. 릴리스는 영속 갱신이 끝난 뒤 첫 결과를 조회한다. | 원본 메타데이터와 최근 일별 행을 복사한다. 복사하는 행 수 기준 공간 `O(F + D_{30})`. 갱신 전체에는 이후 전체 범위 처리 비용이 더해진다. |

두 기준과 현재의 읽기 시간 차수는 선형이고, 중복이 거의 없으면 `U`와 `W`의 차수도 같다. SQLite에서 제거된 `R` 항의 실질 크기는 세션당 요청 수와 날짜·모델 분포에 따라 달라진다. 복잡도의 분자나 변수 정의가 달라지는 지점은 실측 개선율과 구분했다. ## 측정과 재실행

- 빈 스키마 수집, 같은 초기 DB 사본에서의 무변경 갱신과 Codex 요청 1건 추가를 측정했다. 파일 수정, DB 사본 복원, 연결 열기, 검산은 갱신 타이머 밖이다. 원본과 DB를 직접 수정하지 않았다. 운영체제 파일 캐시는 강제로 비우지 않았다.
- Windows x64, Ryzen 5 7500F, Node 24.14.1, SQLite 3.51.2에서 빌드당 새 프로세스와 파일 Worker 4개를 사용했다. 각 입력·작업에서 준비 3회 후 순서를 뒤집으며 10회 측정했다. 피크 V8 힙은 갱신을 실행한 메인 JS 스레드의 `heapUsed`다. RSS는 파일 Worker·Zstd·SQLite를 포함하며, 갱신 시작·종료·진행 콜백과 5 ms 타이머에서 얻은 관측 피크다. 표본 사이의 순간 피크는 포함되지 않을 수 있다.
- 조회는 `Asia/Seoul` 기준 2020-01-01 이상 2035-01-01 미만으로 날짜 미상과 빈 사용량을 포함했다. 제공자별 그룹과 평균 토큰을 전 페이지에서 읽었고, 평균 분모는 각 빌드의 완료 표본이다. 비용 조회는 미측정이다. 현재 확장 초기 설정과 동일하게 도구 수집을 비활성화했다.
- 최근 30일은 2026-10-26부터 2026-11-24까지다. 로컬 입력에서 갱신 시작부터 백엔드가 처음 일별 표를 반환하기까지를 측정했다. 미리보기 콜백이 없으면 영속 갱신 직후 표를 읽었다. VS Code Webview 렌더링은 미측정이다.
- SQLite 크기는 첫 일별 조회 뒤 연결을 닫은 메인 파일이다. WAL·SHM·잠금 DB는 제외했다. 기존 DB 사본은 스키마 이관 직후의 파일 크기와 비어 있지 않은 페이지 크기, 진단용 `VACUUM` 뒤 크기를 별도로 확인했다.
