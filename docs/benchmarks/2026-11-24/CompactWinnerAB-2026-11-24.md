# 파일 준비 결과의 winner 경량화 A/B

파일 공통 관계는 파일 단위로 보관하고, 최종 비교·집계에 쓰는 값만 winner로 넘기면 파일 준비 이후의 힙 사용량이 줄 것으로 예상했다. A는 `f06b2eec0d5668e32b3bdabc8982a0778ad0e890`이다. B는 파일별 비교가 끝난 뒤 최종 응답 비교·귀속, 입력·출력·캐시 토큰, 모델·결제에 쓰는 값으로 snapshot을 구성한다. 진단 플래그와 reasoning은 파싱과 파일 근거 수집에 사용한다. [변경 코드](../../../src/summary/aggregation/sourceWinners.ts)

## 결과

현재 로컬 Claude·Codex JSONL 사본 698파일, 406,744,362바이트를 사용했다. Windows x64에서 Node 24.14.1·SQLite 3.51.2·최대 파일 Worker 4개로, 예열 없이 독립 프로세스와 빈 DB에서 A와 B를 각각 한 번 실행했다. 원본 준비는 타이머 밖에서 수행했다. 표에서 양수는 감소를 뜻한다.

관측 피크 힙은 7.70 MiB 줄었고 최종 집계는 3.97 ms 길어졌다. 전체 시간 차이는 16.31 ms였다. A→B 한 쌍에는 운영체제 파일 캐시와 GC의 영향이 포함될 수 있어 지속적인 속도 개선은 판단을 유보한다. 조회는 빈 DB에 최초 수집한 직후 일·월·세션·프로젝트 순으로 실행했다. 1건 추가, 수정·삭제 갱신, 합성 입력은 미측정이다. [원시 표본·빌드·입력 해시](CompactWinnerAB-2026-11-24.json)

## 정합성

양쪽의 요청 1,523건·토큰 3,147,422,304개, 요청·모델·도구·비용 행 해시, `applied_response` 24,316행의 논리 키·토큰 해시가 일치했다. 네 평균 조회도 전체 페이지를 독립 집계와 대조했고 A/B 결과가 일치했다. 기간은 2020-01-01 UTC 이상 2035-01-01 UTC 미만이며 Asia/Seoul에서 시각 미상을 포함했다. SQLite 무결성·외래 키 검사와 종료 후 입력 파일 해시 확인을 통과했다.
