# 파싱 DTO의 메모리 Map 중복 제거 A/B

측정 기준일: 2026-11-06, Asia/Seoul. 기준은 `80fc586`, 실험 브랜치는 `experiment/jsonl-map-ingestion-2026-11-06`이다. 사용자 지시에 따라 파싱·중복 제거만 변경했다. 제품 `dev` 반영·설치는 수행하지 않았다.

후속 분석 보충(2026-11-07): 이 보고서의 원시 측정값은 보존한다. `batchEvents()`를 메모리 checkpoint로 바꾸면서 같은 함수를 쓰는 이름 metadata UPSERT의 SQL transaction batch도 사라진 부작용을 확인했다. 기존 `readJsonl` 계측에는 대화뿐 아니라 `session_index` 이름 읽기·UPSERT도 포함된다. 따라서 파싱 구간을 순수 대화 DTO 처리 시간으로 해석하거나 후속 갱신의 차이를 Map 선택 자체에 귀속하면 안 된다. [SQL TEMP와 현재 Map의 구간별 직접 비교](./JsonlStageCostAB-2026-11-06.md)에 원인 분리 실험을 기록했다.

현재 상태: 후속 greedy 후보를 철회하고 이 문서의 B인 최초 전체 DTO 방식으로 복원했다. [복원 검증](JsonlDtoRestoreVerification-2026-11-06.json)에서 당시 측정 소스·빌드와의 일치 및 재검증 결과를 확인할 수 있다. 아래 성능 수치는 최초 A/B의 반복 측정값이다.

가정: 파싱 DTO를 먼저 메모리에서 중복 제거하면 중복 이벤트의 SQL 적재와 SQL 응답 순위 계산을 줄일 수 있다. 사용자 요구는 메모리 Map에서 중복 제거·신규 DTO 병합을 끝내고 선택된 결과를 SQL에 적재하는 구조다.

## 현재와의 차이

```text
A: JSONL → 제공자 DTO → TEMP 이벤트 전체 적재 → SQL 중복 제거 → 기존 집계·저장
B: JSONL → 제공자 DTO → 메모리 Map → 중복 제거 → 선택 결과 SQL 적재 → 기존 집계·저장
```

앞선 `SQL → Map → SQL` 후보와 다른 경로다. B의 파싱 중에는 SQL 이벤트 행이 없다. 후보를 SQLite에서 읽어 Map으로 옮기는 SELECT도 없다. 파일 발견·최종 세션 귀속·기존 저장 결과와 dirty 요청 확인에 필요한 metadata 조회는 유지한다.

- 파서가 반환한 정규화 DTO만 메모리에 보관한다. 본문·이미지 Base64·credential은 추가로 보관하지 않는다. 기존의 최대 80자 요청 제목은 유지한다.
- 파일 파싱과 세션 계보가 확정된 뒤 legacy/current 선택과 fork의 동일 접두사를 메모리에서 처리한다. 그 전에 후보를 버리면 복사된 과거 토큰을 판별할 수 없다.
- 응답 Map의 키는 제공자·최종 세션·응답과 Claude canonical request 또는 Codex thread/turn이다. 최고 `input+output` 행을 고르고 동률은 원본 최신 순번을 선택한다. 필드별 max로 원본에 없는 토큰·모델 조합을 만들지 않는다.
- 도구 Map은 제공자·세션·요청·thread·event key·분류·이름이 같은 기록을 하나로 만든다. 제목·상태·완료·검증 이벤트는 기존 의미대로 남긴다.
- 제거한 행이 있던 파일·요청의 존재, 최초 순번과 최소 offset은 무토큰 anchor로 남긴다. 원본 의미 서명과 dirty 전파 의존성은 축약 전 메모리 DTO로 계산한다. 승자만으로 계산하면 다른 root로 이동한 응답과 파일 진단 결과가 달라진다.
- SQL에는 선택된 이벤트·제어 이벤트·필요한 anchor와 품질 flag를 한 번 적재한다. 이후 `winners`는 선택된 usage 행을 가져오는 역할만 하며 응답 순위 정렬이나 중복 제거를 수행하지 않는다.
- 청크마다 하던 TEMP BEGIN/COMMIT을 파싱 경로에서 제거한다. DTO 적재와 metadata 의존 키 적재는 각각 짧은 DEFERRED 트랜잭션으로 묶는다. 중복 제거 외에 이 청크별 트랜잭션 감소도 전체 비용 차이에 포함되며, 내부 요인별 기여도를 분리 측정한 결과는 아니다.
- 갱신 중 메모리 Map을 사용하고 세션 반영 후 해제한다. 영속 DTO/offset 캐시, 추가 구간만 읽기, Worker/LPT, JSONL 리더, 영속 DB 스키마와 조회 SQL은 변경하지 않았다.

## 시간·공간복잡도

`B`는 실제 재파싱 byte, `E`는 필터 전 정규화 이벤트 수, `U`는 응답·도구 고유 키 수, `F`는 파일 수다. 식별자 길이를 고정하고 Map 평균 접근 비용을 상수로 보는 모델이다.

- JSONL 읽기·해석은 기존과 같은 `O(B)`이며, 청크·보관 줄 공간 외에 현재 JSON 객체 공간을 사용한다.
- 응답·도구 Map 선택은 기대 `O(E)`, Map 추가 공간은 `O(U)`다. 요청 ID 보정과 원본 이벤트 처리는 선형 순회한다. 문자열 키 구성 비용은 키 길이에 비례한다.
- 정확한 원본 서명과 fork 접두사 비교 때문에 정규화 DTO를 최종 필터까지 유지하므로 **전체 추가 메모리는 O(E+U)**다. 전체 메모리가 O(U)만 필요하다고 주장하지 않는다. 기존 방식의 FILE TEMP 대신 DTO와 키를 JS heap에 둔 비용을 실제 RSS/heap으로 비교한다.
- 최초 세션·부모 후보 조회와 기존 집계·저장 비용은 별도로 남는다. prefix의 부모 탐색은 현재 단순 파일 탐색을 유지하므로 최악 `O(F²)`이며, Map 선택의 선형성으로 전체 갱신이 선형이 되지는 않는다. metadata 원본 순서 복원에는 root별 정렬이 추가된다.
- 파일 승격과 성분 반영 후 해제는 현재 전체 record Map을 순회한다. 이 호출 횟수를 K라 하면 해당 수명 관리에는 최악 `O(K E)`가 들며, 메모리 선택 단계의 기대 `O(E)`와 구분한다.
- 추가 갱신은 기존과 같이 변경된 파일 전체와 영향받은 세션 원본을 다시 읽는다. 파싱 비용은 `O(추가 byte)`가 아니라 실제 재파싱한 byte에 비례한다. 무변경 본문 읽기는 0이지만 파일 metadata와 이름 index 조회는 남는다.

## 검증과 재현

402개 테스트에서 SQL 적재 전 행 수 0, 실패한 청크 rollback, 독립 승자·정정·동률·누락 요청 ID·큰 정수 합, 중복 도구, legacy prefix, 부모/자식·복사·삭제·재시작·저장 실패 계약을 확인했다. `npm run check`의 타입 검사·린트·전체 테스트를 통과했다. 전체 갱신의 정확성·메모리 검증은 아래 원시 결과와 최종 검증 파일에 보존한다.

실제 로그 560파일·347,801,017byte·1,419요청과 합성 10,000/100요청의 같은 사본을 사용한다. 합성 입력은 고정 순번이며 제공자 교대·10개 프로젝트·14일·세션당 100/10요청이다. 준비 3쌍 뒤 AB/BA 10쌍을 직렬 실행한다. OS 파일 캐시는 비우지 않는다. 추가·복원·DB 열기·스키마 생성·검증은 타이머 밖이며, 전체 갱신은 `refreshSummary` 반환과 세션 COMMIT까지다. 무변경·각 추가 표본은 같은 A seed DB와 같은 원본에서 시작한다. 추가 fixture의 날짜까지 독립 그룹 검증 기간에 포함한다.

각 새 worker 프로세스는 초회→무변경→각 추가 시나리오 순서로 실행한다. DB·원본 사전 상태는 복원하지만 각 시나리오 사이 heap을 강제로 GC하거나 OS cache를 비우지 않는다. 이전 시나리오의 메모리 할당·검증이 이후 cache·GC에 영향을 줄 수 있는 조건이다. 초기 화면의 첫 집계 조회·IPC·UI 시간은 전체 갱신 타이머에 포함하지 않는다.

`parseAndStageMs`는 A에서 JSON 해석·제공자 처리·TEMP 적재, B에서 JSON 해석·제공자 처리·메모리 DTO 추가를 포함한다. `mapMergeMs`는 Map 선택, `selectedLoadMs`는 선택과 SQL 적재를 포함하는 상위 시간이다. 두 값을 더하지 않는다. 별도 진단 1회에서만 JSON.parse·SQL 적재 행 수·메모리를 자세히 계측한다. JSON.parse에는 cached DTO 복원, onRow 시간에는 제공자 처리와 각 방식의 sink가 포함된다. batch 표본은 순간 최대값을 놓칠 수 있고 process high-water는 해당 프로세스의 앞선 준비·검증 구간도 포함한다. 이 수치를 순수 Map 객체 크기로 해석하지 않는다.

기준 A는 `80fc586`을 컴파일해 고정하고 B는 이 워크트리의 소스와 컴파일 결과를 고정한다. 개인 원문·경로·제목 index 사본은 ignored cache에만 두며 보고서에는 값·해시·건수만 저장한다.

```text
node tests/benchmarks/jsonl-map-ab.cjs --before=<고정 A> --after=<고정 B> --output=<새 결과 JSON>
```
