# JSONL 수정 시각 갱신 A/B

[SummaryHeapAudit](../../research/2026-11-20/SummaryHeapAudit-2026-11-20.md)에서 무변경 갱신에도 파일별 체크포인트가 힙에 남고, 모든 로그 본문을 다시 읽는 것을 확인했다. A는 변경 전 `deca0f0`의 전수 prefix 검증과 tail 파싱이다. B는 SQLite의 마지막 성공 갱신 시각으로 후보를 선택하고 후보와 영향 세션의 관련 파일을 처음부터 읽는 방식이다.

## 3. 검증과 해석

- 실제 855요청은 392개 로그·578,269,564바이트의 고정 사본을 사용했다. 합성 입력은 10,000요청·100파일·파일당 100요청과 100요청·10파일·파일당 10요청이다. 합성 Claude·Codex 요청 수를 절반씩 나눴으며 세션과 프로젝트·날짜·토큰을 고정 수식으로 만들었다.
- Windows x64, Node 24.19.0에서 A/B별 독립 프로세스와 최대 4개 파일 Worker를 사용했다. OS 캐시를 유지하며 시나리오당 준비 3쌍과 A→B/B→A 교대 10쌍을 실행했다. 갱신 시간은 탐색부터 마지막 SQLite 트랜잭션까지 포함하며 파일 복원, GC, 정확성 검사 비용은 제외했다. 관측 피크는 5ms 간격과 갱신 진행 콜백에서 수집했다. 힙은 통계 실행 스레드, RSS는 파일 Worker와 SQLite의 네이티브 메모리를 포함한 프로세스 값이다.
- 전체 78쌍에서 요청·모델·도구·비용 facts와 요청 수·토큰 합계, 일별·월별·세션별·프로젝트별 결과 해시가 일치했다. 합성 입력의 최초 합계는 생성기의 기대값과 일치했고, 세 입력 모두 추가 요청의 기대 변화인 +1요청·+130토큰을 확인했다. 평균 조회는 2020~2035년과 날짜 미상 요청을 포함하고 Asia/Seoul, 완료 요청 분모를 적용했다. 네 그룹 결과를 독립 JavaScript 합산으로 624회 대조했다.
- 파일 수 F, 전체 본문 바이트 N, 추가 tail 바이트 D, 선택·관련 파일 본문 바이트 B를 기준으로 두 방식의 탐색은 O(F)다. A는 무변경과 정상 append에도 O(N)을 읽고 append tail을 O(D)로 파싱한다. B는 O(B)을 읽고 파싱하므로 무변경의 본문 비용은 0이고, 긴 관련 세션 전체를 읽는 비용이 생긴다. A는 파서·winner를 전체 파일에 대해 계속 보관한다. B의 갱신 중 DTO 크기는 재파싱하는 세션에 비례하고, 종료 후 증분 판정값은 SQLite 한 행에 남는다. 최초 수집의 전수 파싱·집계 피크 비용은 양쪽에 있다.
- 갱신 기준보다 오래된 mtime으로 복사하거나 이동한 파일, mtime을 이전 값으로 복원한 내용 변경은 증분 대상에서 빠질 수 있다. 긴 한 세션에 전체 본문이 집중된 입력의 별도 A/B와 v20→v21 SQLite 마이그레이션 시간은 미측정이다.

원시 표본과 입력·빌드 해시는 [JSON](MtimeRefreshAB-2026-11-21.json)에 있다. 선택한 실제 로그의 경로와 본문은 저장하지 않았다.

## 재실행

A는 `deca0f00622589aa823688d05f91d2d89506df61`의 별도 작업 트리에서, B는 수정 시각 방식의 소스에서 각각 `npm run build`로 준비한다. A 경로는 `src`와 `dist`가 있는 작업 트리를 지정한다. 실행기는 원본 경로에서 로그를 고정 사본으로 만들어 사본에서만 추가·복원한다.

```powershell
node --no-warnings tests/benchmarks/mtime-refresh-ab.cjs --before="C:/work/Agent-Tracker-A" --after=. --output=tests/results/benchmarks/mtime-refresh.json
```
