# SQLite 일별 기본 키 날짜 우선 A/B 테스트

사용자는 날짜를 기준으로 일별 테이블을 클러스터링해 직전과 동일한 A/B 비교를 요청했다. 날짜를 기본 키 첫 컬럼으로 옮기면 하루나 최근 30일처럼 기간을 좁힌 조회는 빨라지고, 날짜 범위 없이 세션을 찾는 조회는 느려질 것으로 예상했다.

A는 `a9b1290`의 v27로 기본 키는 `(provider, session_id, project_key, local_day[, model_key])`다. B는 실험용 v28로 기본 키는 `(local_day, provider, session_id, project_key[, model_key])`다. 두 빌드 모두 별도 보조 인덱스 0개이고 일별 저장 단위와 집계 값은 동일하다.

## 1. 결과

시간은 실측 10쌍의 중앙값 ms다. 괄호는 `(A − B) ÷ A`의 백분율이며, 양수는 감소를 뜻한다.

Windows x64, Ryzen 5 7500F, Node 24.14.1, SQLite 3.51.2와 파일 Worker 4개로 측정했다. 준비 실행 3쌍 후 A→B와 B→A를 교대해 10쌍을 실행했다. 운영체제 파일 캐시는 비우지 않았다. 갱신 시간은 DB를 연 뒤 원본 스캔부터 커밋과 반환까지다. 파일 추가와 DB 복원은 타이머 밖에서 처리했다.

[직전 실험](SQLiteIndexRemovalAB-2026-11-25.md)의 로그 사본을 이 실험용 폴더에 복사했다. 입력 해시와 1건 추가에 사용한 로그 해시가 세 규모에서 일치했다. 실로그는 Claude 12개와 Codex 702개다. 합성 입력은 제공자 비율이 절반씩이고, 1만 건은 100세션·세션당 100요청, 100건은 10세션·세션당 10요청이다. 평균 조회는 요청 1건을 추가한 뒤 `Asia/Seoul` 기준 2020-01-01 이상 2035-01-01 미만에서 미상 날짜를 포함한 제공자별 결과의 전체 페이지를 읽었다. 평균은 완료 표본의 합계와 표본 수로 계산했다.

준비를 포함한 143쌍에서 토큰 합계, 스레드 수, 평균과 그룹 수가 일치했다. 원본 JSONL의 독립 입출력 검산과 합성 입력의 예상 토큰을 확인했다. 1건 추가 뒤에는 양쪽 모두 130토큰 늘었다. SQLite 무결성과 외래 키 검사, 입력 복원 해시 확인을 통과했다. [원시 결과](DailyDateClusterAB-2026-11-25.json)

## 2. 분석

- **날짜 범위 조회** — 실로그에서 준비된 첫 페이지 SQL의 하루 조회는 0.116→0.100 ms로 13.8% 줄었고, 최근 30일은 0.342→0.323 ms로 5.5% 줄었다. `EXPLAIN QUERY PLAN`에서 `SCAN usage` 또는 제공자 기본 키 탐색이 `SEARCH usage USING PRIMARY KEY (local_day>? AND local_day<?)`로 바뀌었다. `GROUP BY`용 임시 B-tree는 유지됐다.
- **세션별 조회** — 날짜 범위 없이 특정 세션을 조회할 때는 `(provider, session_id)` 기본 키 탐색이 `SCAN usage`로 바뀌어 0.105→0.127 ms였다. 전체 기간 세션별 첫 페이지 SQL에는 `USE TEMP B-TREE FOR GROUP BY`가 추가됐다. 세션의 최초 시각을 구하는 상관 하위 쿼리에서도 `(provider=? AND session_id=?)` 탐색이 사라졌다. 100행을 반환하는 첫 페이지 SQL은 2.079→11.795 ms였고, 전체 페이지 조회는 3.675→11.656 ms였다. 날짜 및 세션별 SQL은 준비 3쌍과 교대 10쌍으로 실행했고 각 쌍에서 하루 쿼리는 400회, 나머지는 80회씩 반복했다.
- **갱신** — 실로그 1건 추가의 차이는 0.24 ms였다. 쌍별 차이가 −10.62~+3.48 ms여서 같은 환경에서 방향이 반복돼 나타나지는 않았다. 최근 30일 화면을 열었을 때의 첫 결과도 빈 DB 1,402.86→1,392.51 ms, 1건 추가 192.75→191.04 ms로 변동 폭 안이었다.
- **이관 및 공간** — v27 실로그 사본의 이관과 연결 열기는 22.98 ms가 걸렸다. 파일은 960→1,104 KiB였고, 이관 직후 점유 공간은 960 KiB였다. 남은 144 KiB는 재사용 가능한 페이지다. 측정용 사본을 `VACUUM`하면 916 KiB였다. v26과 v27 이관 사본의 제품 테이블 8개에서 전체 행을 대조했다.

**결정** — 전체 기간 월별 조회가 28.0% 느려졌고, 전체 기간 세션별 조회도 10쌍 모두 느려졌다. 날짜 우선 배치는 실험으로 종료하고 제품 코드를 v27 세션 우선 기본 키로 되돌렸다.

## 재실행

[이전 A/B의 빌드 준비와 실행 명령](SQLiteIndexRemovalAB-2026-11-25.md#재실행)에서 A 사본은 `a9b1290` 소스로 `session-first` 폴더에 컴파일한다. B는 실험 당시 `tests/.cache/daily-date-cluster-ab-2026-11-25/current`에 보존한 후보 빌드를 사용한다. 실행 명령의 비교 대상과 독립 검산 대상에 있는 `indexed`를 `session-first`로 바꾼다. 실험에서는 이전 입력 사본을 새 폴더에 복사하고 `snapshot.private.json`의 절대 경로를 새 폴더로 옮긴 뒤 같은 입력 해시로 재실행했다.
