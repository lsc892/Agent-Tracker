# 갱신 트랜잭션을 기준으로 집계 월 PK 철회

측정일: 2026-10-31, Asia/Seoul. 목표는 **업데이트 쓰기 트랜잭션 시간을 줄이는 것**이다. 월 조회 개선율로 일별 집계 월 PK를 채택한 판단을 정정하고 **기존 세션 PK + 큰 세션의 선택적 묶음 비교**로 변경했다.

## 1. 기존 월 조회는 얼마나 걸렸나

[앞선 동일 입력 측정](StorageProduct-final-2026-10-31.json)에서 실제 DB 1,100건의 전체 월 조회는 제공자 **1.215ms**, 모델 **1.584ms**였다. 월 PK로 각각 0.692ms·1.246ms가 되어 절감은 약 **0.523ms·0.338ms**였다. 이것은 warm DB 페이지 조회 시간이며 UI 전체 응답 시간이 아니다.

이 작은 절대 시간 절감을 위해 갱신 지연과 저장 공간을 늘리는 선택은 이번 목표에 맞지 않았다. 다만 합성 10만 건/세션100의 전체 월 조회는 기존 약 231ms·393ms였으므로 모든 규모의 조회가 1ms였다는 뜻은 아니다. 이번 결정의 우선 기준을 쓰기로 바로잡는다.

**실험 범위도 정정한다.** 당시 월 PK로 바꾼 것은 usage_request_daily·usage_model_daily 두 집계 표였다. 요청 본체 turn_summary는 정수 행 ID와 기존 요청 UNIQUE 인덱스를 유지했다. 따라서 원본 요청 본체의 월별 클러스터링이 갱신에 도움이 되는지까지 검증한 결과는 아니다.

## 2. 실제 쓰기 구간의 시간·공간 트레이드오프

기존 세션 PK·일괄 저장, 월 PK·일괄 저장, 월 PK·묶음 비교, 세션 PK·묶음 비교의 **네 제품 빌드**에 동일 입력을 주었다. 표의 시간은 **BEGIN IMMEDIATE 성공 직후부터 COMMIT 반환까지**의 5회 중앙값이다. 잠금 획득 호출 시간과 입력 복제를 포함한 저장 호출 전체 시간은 원시 JSON에 따로 기록했다.

각 증감률은 같은 행의 **기존 세션 PK·일괄 저장** 대비다. TEMP·WAL·집계 공간도 같은 기준에서 **현재 세션 PK·선택적 묶음 비교**와 대조했다. 소수 변경의 자동 부분 반영은 기존 1,000건 이상이면서 변경·추가·삭제가 10% 이하·최대 32건일 때 사용한다. 더 작으면 일괄 경로, 변경이 많으면 TEMP 비교 후 일괄 반영한다.

10,000건 세션 한 건 추가의 쓰기 구간은 **801.791→431.769ms, 46.1% 감소**했다. 같은 작업의 입력 복제 포함 저장 호출 전체는 843.749→474.839ms, 43.7% 감소했다. 앞서 적용했던 월 PK+묶음 상태에서도 세션 PK로 복원하면 474.597→431.769ms, 9.0% 감소했다.

변경 없는 같은 세션은 쓰기 구간 801.099→244.735ms, 69.5% 감소했다. 전건 변경은 822.043→926.832ms, **12.7% 증가**했다. 모든 갱신이 빨라진 설계는 아니다.

1,000건 미만은 묶음 반영이 실행되지 않는다. 이 행의 차이는 경로 선택 확인 비용과 표본 편차를 포함하므로 묶음 반영의 이득으로 해석하지 않는다. TEMP는 종료 시 할당된 페이지 용량으로 빈 페이지·이전 할당을 포함하고 RSS 피크가 아니다. WAL은 측정 직전 checkpoint 후 종료 시 파일 길이로 누적 쓰기 바이트가 아니다. 집계 live 공간은 본체·인덱스·meta의 dbstat 페이지 합계이며 빈 페이지는 제외한다.

## 3. 현재 적용과 남는 병목

schema v16은 집계 PK를 (provider,session_id,project_key,local_day[,model_key])로 복원하고 월 컬럼·세션/월 목록·월 prefix 수집을 제거했다. 기존 v13의 형식 v1 캐시는 재사용한다. 실험 버전 v14·v15는 원본 요청·ID·모델·비용·Skill·manifest를 보존하고 파생 캐시만 지운 뒤 첫 조회에 다시 구축한다. 원본 로그 재파싱은 필요 없다.

실제 변경이 있으면 집계는 여전히 대상 세션 전체를 재계산한다. 입력 N건과 모델·Skill을 검증·TEMP 적재·비교하는 작업도 **쓰기 트랜잭션 안**에 남는다. 영속 쓰기를 변경분으로 줄였어도 전체 갱신이 O(1)이 되거나 잠금 보유 시간이 사라진 것은 아니다. 집계 하위 구간은 원시 JSON의 rollupMs로 분리했다. 각 구간 중앙값은 서로 다른 표본에서 나올 수 있어 더해 전체 시간으로 사용하지 않는다.

사용자 목표에 비춰 이번 집계 월 PK의 채택은 철회했다. 요청 본체의 월별 배치나 비교 준비의 잠금 밖 이동을 평가하려면 요청 본체 쓰기·집계·검증·COMMIT과 실제 경합 대기를 구분해야 한다. 이번 측정은 경합 없는 한 쓰기 연결에서의 보유 구간을 확인한 것이며 실제 다른 창의 대기 감소까지 입증하지 않는다.
