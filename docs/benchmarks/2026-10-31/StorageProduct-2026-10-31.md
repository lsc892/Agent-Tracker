# 월 PK와 큰 세션 묶음 비교의 실제 제품 증감률

후속 결정: 사용자 목표는 **업데이트 쓰기 트랜잭션 단축**이었다. 월 조회의 상대 개선율을 근거로 집계 월 PK를 채택한 판단을 정정하고 세션 PK를 복원했다. 현재 구현과 트랜잭션 직접 측정은 [쓰기 트랜잭션 비교](StorageTransactions-2026-10-31.md)를 따른다. 아래는 당시 월 PK 실험의 저장 호출 전체 시간이며 원시 결과는 보존한다.

측정: 2026-10-31, Asia/Seoul. [최종 원시 결과](StorageProduct-final-2026-10-31.json)의 동일 입력·5회 중앙값으로 계산했다. 비교 시작점은 이 작업 전의 **세션 PK·스트리밍 일괄 저장 제품**이다. 증감률은 (변경 후/변경 전−1)×100이며, 음수는 감소·양수는 증가로 표시한다. 비율은 반올림 전 중앙값으로 계산하고 시간은 소수 셋째, 비율은 첫째 자리로 표시한다.

기간 조회 이득과 세션 갱신·탐색 비용을 함께 봐야 한다. 한 달 조회는 미상 시각도 포함하는 제품 기본 정책이며 미상 제외는 원시 JSON의 one-month-known에 있다. **집계 공간**은 두 일별 본체·보조 인덱스·세션·월 목록·meta의 live 페이지 합계다. **전체 live DB**는 facts와 다른 테이블·인덱스도 포함하며 빈 페이지·WAL은 제외한다. 전체 파일 길이나 메모리 사용량을 뜻하지 않는다.

월 PK만 바꾸면 세션별 삭제·조회에서 전체 스캔이 발생했다. [초기 제품 대조](StorageProduct-hybrid-2026-10-31.json)에서는 10만 건/세션 100건의 한 건 추가가 13.809→119.669 ms였고, [보조 목록 도입 전](StorageProduct-preDirectory-2026-10-31.json)의 특정 세션 조회도 약 0.559→84 ms(제공자), 0.86→284 ms(모델)로 악화됐다. [목록 갱신의 첫 구현](StorageProduct-directoryV1-2026-10-31.json)도 IN 조건이 넓은 보조 인덱스 범위를 읽어 한 건 추가가 20.955→86.944 ms로 악화됐다. 최종 구현은 이전·새 월 prefix로 삭제 범위를 제한하고, 세션 조회와 목록 갱신 모두 작은 월 목록부터 CROSS JOIN해 본체 PK를 탐색한다. 최초 시각도 그 목록에서 계산한다. **위 표는 이 보완을 포함한 결과**다. 목록 저장 공간을 숨긴 순수 PK 순서만의 비교가 아니다.

세션·월 목록 규모: synthetic-1200-25: 86행, synthetic-6000-300: 78행, synthetic-10000-1000: 39행, synthetic-100000-100: 3,928행, synthetic-100000-10000: 39행, installed-snapshot: 395행. 새 마이그레이션은 원본 ID·facts·모델·비용·Skill·manifest를 보존하고 파생 캐시만 비운다. 첫 조회에 재구축하므로 위 warm 시간 외에 최초 구축 비용이 한 번 필요하다.

설치 DB의 가장 큰 세션은 25건이므로 묶음 반영을 사용하지 않는다. 작은 세션의 월 PK/최종 차이는 같은 저장 경로의 표본 편차이며 묶음 비교의 개선으로 해석하지 않는다. 두 단계의 영속 스키마는 같지만 물리 페이지 점유는 쓰기 이력에 따라 달라진다: 300건 세션 입력의 전체 live DB 3.438→3.438 MiB; 1,000건 세션 입력의 전체 live DB 4.000→4.004 MiB; 10,000건 세션 입력의 전체 live DB 33.016→33.016 MiB.

WAL은 호출 전 checkpoint 후 호출 종료 시점의 **파일 길이**이며 누적 쓰기량이 아니다. TEMP는 호출 종료 후 TEMP DB에 **할당된 페이지 용량(빈 페이지 포함)**이다. 이전 호출에서 재사용하는 공간을 포함하며 현재 live 데이터·정렬 임시 파일·heap/RSS 피크를 뜻하지 않는다. 동일 snapshot의 WAL 0은 files:[]인 이번 DB 저장 실험 결과이며 실제 refresh 전체의 무쓰기를 뜻하지 않는다.

## 3. 남는 시간·공간 복잡도와 선택 근거

월 PK는 월 범위의 본체 접근과 월 그룹 정렬을 줄인다. 전체 기간은 여전히 집계 행 수에 비례해 읽고, 보조 목록은 세션·월 수에 비례하는 공간을 추가한다. 원본 요청의 저장량 차수를 바꾸지는 않는다.

묶음 비교도 입력 N건과 모델·Skill 전체를 검증·적재·비교하므로 **N 전체를 보는 비용이 남는다**. TEMP 공간은 입력 요청·자식 행 수에 비례한다. 소수 변경은 영속 facts·자식의 쓰기 범위를 변경분으로 줄이지만 실제 변경이 있으면 집계는 세션 전체를 재계산한다. 따라서 한 건 추가 전체가 O(1)로 바뀌었다고 볼 수 없다. 변경 없는 요청의 ID·updated_at을 유지하고 동일 큰 snapshot은 facts·비용·집계 쓰기를 생략한다.

[300건 후보 대조](StorageProduct-candidate300-2026-10-31.json)에서는 한 건 추가가 5쌍 중 2쌍만 빨랐고 날짜 이동·삭제 중앙값은 각각 4.9%·13.4% 악화됐다. 1,000건 이상은 소수 변경 이득이 더 일관돼 최소 크기를 올렸다. **1,000건은 이번 분포에서 정한 보수적 초기 정책**이며 모든 분포의 최적 경계는 아니다. 파일 tail 파싱·정규화 캐시·이벤트 캐시는 이번 변경에 포함하지 않는다.
