# 읽는 즉시 응답별 최고값을 고르는 스레드 집계 A/B

파일에서 중복 응답을 먼저 제거하고 받은 최고값을 바로 합치면 집계 단계의 재순회와 프로세스 메모리를 줄일 수 있다고 예상했다. A는 파일별 응답·누계 배열을 모으던 직전 구현으로, 이전 실험의 B 빌드와 소스·컴파일 해시가 같다. B는 파일을 읽는 동안 응답별 최고값을 선택하고, 도착 즉시 병합하며 Codex 검산에 필요한 누계 구간만 남긴다. [직전 실험](ResponseThreadAccountingAB-2026-11-24.md) · [현재 필드와 합산 규칙](../../../refrences/LogParsingFields.md)

## 결과

직전 실험에서 고정한 Claude 12파일과 Codex 691파일을 사용했다. 전체 429,580,467바이트이며 668파일은 압축 로그다. Windows x64, Node 24.14.1, SQLite 3.51.2, 파일 Worker 4개와 `Asia/Seoul` 시간대에서 각 빌드를 새 프로세스와 빈 DB로 한 번씩 A → B 순서로 실행했다. 예열과 운영체제 파일 캐시 초기화는 없었다. [원시 표본과 빌드·입력 해시](StreamingThreadResponseAB-2026-11-24.json)

| 항목 | 변경 전 | 변경 후 | 변화 |
| --- | ---: | ---: | ---: |
| 최초 수집·저장 | 4,037.77 ms | 3,673.92 ms | 363.85 ms 감소 (9.01%) |
| 변경 원본 준비 | 3,714.05 ms | 3,399.61 ms | 314.44 ms 감소 (8.47%) |
| 최종 스레드 집계 | 44.31 ms | 10.56 ms | 33.75 ms 감소 (76.17%) |
| 프로세스 피크 RSS | 475.05 MiB | 451.99 MiB | 23.07 MiB 감소 (4.86%) |
| 메인 JS 힙 피크 | 42.62 MiB | 45.09 MiB | 2.47 MiB 증가 (5.79%) |
| 수집 종료·강제 GC 후 RSS | 263.97 MiB | 244.61 MiB | 19.36 MiB 감소 (7.33%) |

RSS는 파일 Worker와 네이티브 영역을 포함한 프로세스 값이다. 힙 표본은 수집 프로세스 메인 스레드 값이며 두 지표 모두 5ms 간격과 수집 진행 시점에 표본을 얻었다. 최종 집계 구간의 감소에는 일부 병합 작업이 원본 준비 단계로 이동한 효과도 포함된다. 이번 표본에서 전체 수집 시간과 RSS가 줄고 메인 힙 피크는 늘었다. 두 실행의 캐시·GC 영향과 Worker별 메모리 기여도는 계측하지 않았으므로 한 쌍에서 얻은 차이로 본다.

## 정합성

변경 전후 각각 Claude 10,241,517토큰과 Codex 3,461,396,291토큰으로, 합계 **3,471,637,808토큰**이었다. 각 제공자의 입력·출력도 원본 JSONL을 별도로 해석한 결과와 일치했다.

스레드 684행, 모델 689행, 비용 684행 및 원본 상태 703행의 정규화 해시가 전후 일치했다. 스레드 시간·상태 및 모델별 입출력·캐시 토큰을 확인했다. 제공자별·모델별 전체·일·월·세션·프로젝트 조회의 모든 행을 비교해 합계와 평균이 일치했다. 두 DB 모두 SQLite 무결성과 외래 키 검사를 통과했다. [정합성 검사 코드](../../../../tests/benchmarks/thread-usage-ab.cjs)

이번 범위는 실제 로그 최초 수집 1쌍이다. 1건 추가, 무변경 갱신, 합성 10,000건과 100건은 미측정이다. 조회별 시간의 단일 표본은 원시 JSON에 기록했다.

```powershell
node --no-warnings tests/benchmarks/thread-usage-ab.cjs '<A 빌드 루트>' '<B 빌드 루트>' '<고정 입력 manifest>' '<새 JSON 출력>' --same-stats
```
