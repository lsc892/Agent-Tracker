# SQLite 보조 인덱스 제거 A/B 테스트

사용자는 SQLite의 보조 인덱스를 제거하고 갱신 시간과 DB 크기의 변화를 측정해 달라고 했다. 인덱스 페이지와 쓰기 작업은 줄고, 좁은 날짜 범위 조회는 스캔 비용이 늘 것으로 예상했다. A는 `b330061`의 스키마 v26이다. B는 보조 인덱스 여섯 개를 제거하고 v27 이관을 추가했다. 두 빌드의 기본 키, 고유 제약과 집계 SQL 본문은 같다.

## 1. 결과

시간은 10쌍의 중앙값 ms다. 괄호의 양수는 감소율, 음수는 증가율이다.

Windows x64, Ryzen 5 7500F, Node 24.14.1, SQLite 3.51.2에서 새 프로세스와 파일 Worker 4개를 사용했다. 작업마다 준비 실행 3쌍 뒤 A→B와 B→A를 교대해 10쌍을 측정했다. OS 캐시를 비우지 않았다. 갱신 시간은 DB를 연 뒤 스캔부터 COMMIT과 갱신 반환까지다. 원본 복사, 로그 추가, DB 복원과 검산은 타이머 밖이다. 파일 크기는 연결 종료 후의 메인 DB이며 WAL·SHM은 제외했다.

실로그는 Claude 12개, Codex 702개의 고정 사본이다. 합성 로그는 고정 산식으로 생성한 두 제공자 절반씩의 입력이다. 각 규모는 100세션·세션당 100요청과 10세션·세션당 10요청이다. 세션은 7월 1일부터 14일에 분포하며 모델은 제공자마다 두 종류다. 제공자별 평균 조회는 `Asia/Seoul` 기준 2020-01-01 이상 2035-01-01 미만에서 완료 표본과 미상 날짜를 포함해 전체 페이지를 읽었다. 평균 조회 표에는 1건 추가 후 실행 시간을 사용했다.

준비를 포함한 143쌍에서 토큰 합계·스레드 수·조회 그룹과 평균이 일치했다. 원본 JSONL을 독립적으로 검산한 입출력 합계와 합성 입력의 기대 토큰이 일치했고, 같은 요청을 추가하면 양쪽 Codex 집계에 130토큰이 늘었다. SQLite 무결성·외래 키 검사와 원본 사본의 복원 후 해시 확인을 통과했다. 실로그의 새 DB 및 이관 사본에서 파일 기록 시각을 제외한 제품 테이블 여덟 개의 행 내용이 일치했다. [원시 표본과 소스·입력 해시](SQLiteIndexRemovalAB-2026-11-25.json)

## 2. 분석

- **갱신** — 실로그 최초 수집의 저장 트랜잭션 구간은 87.04→79.07 ms, 일별 UPSERT 합산은 23.89→22.72 ms였다. 요청 1건 추가의 저장 구간은 16.33→15.53 ms, UPSERT는 11.01→10.75 ms였다. UPSERT 호출은 최초 수집 54회, 1건 추가 2회로 양쪽이 같았다. 전체 갱신 단축 폭은 개별 측정쌍의 변동 범위 안이고 1건 추가에서는 방향이 규모별로 달랐다.
- **공간** — 실로그에서 보조 인덱스 여섯 개는 총 476 KiB를 점유했다. 기존 DB 사본을 v27로 열었을 때 파일은 1,424 KiB였고 점유 공간은 948 KiB였다. 4 KiB 페이지 119개를 회수해 재사용할 수 있게 됐다. 측정용 사본을 `VACUUM`한 뒤에는 916 KiB였다. 이관과 연결 열기의 1회 관측값은 4.69 ms였다.
- **조회** — 넓은 기간을 읽는 실로그 조회의 중앙값은 감소했다. 최신 날짜 하루의 결과 1행을 조회할 때는 `idx_usage_request_daily_day` 범위 탐색이 테이블 스캔으로 바뀌었고, 준비된 SQL의 실행 시간은 0.105→0.124 ms로 약 18% 늘었다. 같은 날짜와 페이지에서 쿼리당 400회씩 준비 3쌍과 교대 10쌍을 측정했다.

## 재실행

[기존 빌드 준비 절차](../2026-11-24/HistoricalSummaryAB-2026-11-24.md#측정과-재실행)를 사용한다. `indexed` 폴더에는 `b330061`, `current`에는 v27 후보 소스를 컴파일한다. 기존 [갱신 측정기](../../../../tests/benchmarks/historical-summary-ab.cjs)의 비교 대상만 두 빌드로 지정한다. 다음 명령은 준비한 폴더에서 동일한 세 규모를 측정하고, 기존 사본이 있으면 그 입력을 재사용한다.

```powershell
$benchRoot = 'tests/.cache/index-removal-ab-2026-11-25'
$indexAbLauncher = @'
const fs = require('node:fs');
const Module = require('node:module');
const path = require('node:path');
const runner = path.resolve('tests/benchmarks/historical-summary-ab.cjs');
const source = fs.readFileSync(runner, 'utf8')
  .replace("const revisions = ['9627303', 'fd83620', 'current'];", "const revisions = ['indexed', 'current'];")
  .replace("join(workspace, '9627303')", "join(workspace, 'indexed')")
  .replace('revisions.slice(0, 2)', 'revisions.slice(0, 1)');
process.argv[1] = runner;
const benchmark = new Module(runner, module);
benchmark.filename = runner;
benchmark.paths = Module._nodeModulePaths(path.dirname(runner));
benchmark._compile(source, runner);
'@
$indexAbLauncher | node --no-warnings - $benchRoot (Join-Path $benchRoot 'results.json') 10 3
```
