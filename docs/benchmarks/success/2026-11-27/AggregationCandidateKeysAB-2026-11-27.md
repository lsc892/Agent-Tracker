# 대화·응답 키 직렬화 절감 A/B

사용자는 세션 응답을 병합할 때 대화 조회 키와 중복 비교 키를 매 후보마다 만드는 비용을 줄이고 효과를 확인하도록 요청했다. 에이전트는 두 복합 키를 없애면 집계의 임시 힙과 시간이 줄어들 것으로 가정했다.

A는 `f00a22a`의 두 복합 키를 사용하는 집계다. B는 제공자·세션별 맵에서 `rootId`로 대화를 찾고, 응답 후보를 원래 ID 필드로 정렬한다. Claude의 요청 ID 보정, 응답 점수, 동점 및 반영 순서를 유지한다. 확정 응답 키를 받는 콜백이 등록된 경우에는 반영 시 같은 형식의 키를 생성한다. [집계 코드](../../../../src/summary/aggregation/memoryAggregate.ts) · [응답 중복 제거 정책](../../../refrences/WinnerPolicy.md)

## 판정

- 실로그 최초 수집 피크 힙은 **14.45 MiB**(20.6%) 낮아졌고 20쌍 중 19쌍이 감소했다. `finish()` 중 힙 증가량은 **61.6%** 낮아졌다. 실로그와 합성 10,000대화에서 집계 시간과 `finish()` 직후 힙이 각각 20쌍 모두 줄었다.
- 최초 수집 전체 시간은 실로그에서 중앙값이 26.69 ms 늘었고 쌍별로는 20쌍 중 13쌍이 빨랐다. 로그 준비가 실로그 최초 수집의 약 90%였으며, 전체 시간·RSS·증분 및 조회에서는 뚜렷한 개선을 확인하지 못했다. 합성 100대화에서는 최초 피크 힙이 0.06 MiB 늘었다.
- 대화 맵 조회와 응답 비교 키에서 후보당 기본 직렬화 두 번을 제거했다. 두 변경을 함께 측정했으며, 개별 변경의 기여도와 누적 할당량은 따로 측정하지 않았다. 최초 수집의 집계 힙과 시간 감소를 근거로 B를 반영했다.
