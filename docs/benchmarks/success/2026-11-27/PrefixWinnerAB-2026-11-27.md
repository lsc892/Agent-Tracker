# Codex 행 접두사와 응답 winner A/B

사용자는 접두사로 행 종류를 판별해 필요한 값만 읽고, 비교에서 이긴 응답만 객체로 만들어 달라고 요청했다. A는 `51a7d1f`다. B는 알려진 형식의 완성된 Codex `response_item`에서 시각을 직접 읽고 본문은 문법만 검사한다. 그 밖의 행에는 고정 필드 선택기를 쓰며 문자열·컨테이너 상태를 재사용한다. Claude와 Codex의 응답 객체는 기존 점수와 비교한 뒤 생성한다. 응답 기록의 토큰과 구형 누계는 고정 필드 선택 경로에서 해석한다.

## 시간

각 셀은 A → B 중앙값 ms와 개선율이다. 양수는 단축이다.

Windows x64, Ryzen 5 7500F, Node 24.14.1, SQLite 3.51.2, Asia/Seoul에서 파일 Worker를 최대 4개로 실행했다. 실로그는 Claude 12파일과 Codex 721파일이며 Codex 668파일은 Zstd였다. 독립 검산에서 현재 형식 Codex 응답 19,526개와 Claude 응답 100개를 관측했고 구형 Codex 누계가 있는 파일은 180개였다. 저장 결과는 스레드 714개였다. 합성 입력은 Claude·Codex가 절반씩이며 200·20세션, 세션당 50·5응답이다. 기록은 2026년 7월 1~14일에 분포하며 제품의 경로 기준 집계에서 제공자·프로젝트 그룹 두 개가 나온다. 조회는 시각 미상까지 포함한 전체 기간과 완료 스레드 분모를 사용했다.

세 입력의 최초 수집과 1건 추가 각각에서 준비 3쌍 뒤 AB 10쌍, BA 10쌍을 교대했다. 매 표본은 새 프로세스에서 실행했다. 최초 수집은 빈 DB, 추가 수집은 같은 기준 DB 사본에서 시작했다. 갱신에는 원본 읽기·파싱·집계·COMMIT·파일 Worker 종료가 포함된다. OS 파일 캐시는 유지했고 사본 복원과 검산은 타이머 밖에서 했다. [원시 시간·저장 검증](PrefixWinnerAB-2026-11-27.json)

## 정합성과 판정

- 고정 필드 선택 결과와 바이트 위치는 실로그 227,584행, 합성 30,100행과 310행에서 일치했다. 제품 경로를 사용한 측정 120쌍에서 원본 관측·본문 읽기량, SQLite 논리 행, 네 평균 조회에서 건수·토큰·그룹·평균이 일치했다. 독립 JSONL 검산과 SQLite 무결성·외래 키 검사를 통과했다. 모든 입력의 응답 1건 추가는 130토큰 증가했다.
- 제품 경로 회귀 검사는 알려진 접두사, 중복 키가 있는 행의 기존 경로, 문법 오류와 원본 바이트 위치, 청크 경계, 미완성 줄 보류와 동점 winner를 대조했다. JSONL·Zstd 관련 테스트 19개가 통과했다.
- `npm run check`의 타입 검사와 린트는 통과했다. 기준 빌드는 Node 테스트 448개 중 234개가, 후보는 449개 중 235개가 통과했다. 실패한 214개 테스트의 이름은 양쪽에서 일치했다.
- 할당 감소 가정은 성립했다. 지연 감소 가정은 기각했다. 실로그 최초 수집과 변경 원본 준비가 20쌍 모두 느려져 비용이 파싱·준비 구간에서 발생함을 확인했다. 접두사 분기와 상태 재사용의 개별 비용은 분리 계측하지 않았다. 1건 추가와 평균 조회의 A/B 범위는 겹쳤다. 상태를 깊이별로 관리한 소규모 후속 비교에서도 실로그 첫 수집이 3,065.03 → 3,350.54 ms였다.
- 메모리 절감 요청에 맞춰 전체 A/B를 완료한 B를 작업 트리에 적용했다. 실로그 최초 수집 지연과 소규모 입력 피크 힙 증가는 관측된 비용이다.
