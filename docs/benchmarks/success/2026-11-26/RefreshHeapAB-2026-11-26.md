# 원본 탐색과 Codex 응답 키 색인의 힙 A/B

실로그 733파일을 현재 작업 트리로 다시 프로파일링했다. 통계 Worker에서 디렉터리 순회 `walk`의 누적 할당 추정이 46.22 MiB였고, 집계 직전 GC를 거친 뒤에도 Codex 응답 병합에 약 2.70 MiB가 남았다. A는 미커밋 변경까지 포함한 작업 시작 시점의 소스 사본이다. B는 발견한 로그를 그 위치에서 직접 관측하고, 파일 안에서 이미 중복을 제거한 응답은 복사본이나 누계 구간을 비교할 때만 턴·응답 키 색인을 만든다.

## 갱신과 평균 조회

각 셀은 A → B 중앙값이다. 시간 단위는 ms다. 평균 조회는 요청 한 건 추가 후 일·월·세션·프로젝트별 전체 결과를 받아 저장된 완료 스레드 수를 분모로 대조했다.

| --- | ---: | ---: | ---: |
| 최초 수집 | 3,017.11 → 3,009.54 | 350.46 → 350.29 | 35.34 → 35.21 |
| 무변경 갱신 | 131.80 → 125.93 | 30.44 → 30.70 | 7.85 → 7.73 |
| 요청 1건 추가 | 250.51 → 247.85 | 53.96 → 52.64 | 27.88 → 27.33 |
| 일별 평균 토큰 조회 | 1.87 → 1.90 | 1.22 → 1.31 | 1.11 → 1.00 |
| 월별 평균 토큰 조회 | 0.80 → 0.78 | 0.53 → 0.54 | 0.44 → 0.40 |

Windows x64·Node 24.14.1·SQLite 3.51.2·Asia/Seoul에서 조건마다 준비 3쌍 뒤 A→B와 B→A를 10쌍씩 교대했다. 실로그는 직전 벤치마크의 고정 사본이며 Claude 12파일과 Codex 721파일에서 스레드 714개가 저장됐다. 합성 입력은 Claude와 Codex 각각 절반을 차지하며 세션당 50·5응답으로 총 200·20세션이다. 갱신마다 새 프로세스를 사용했다. 최초 수집은 빈 DB에서, 무변경과 한 건 추가는 같은 기준 DB의 사본에서 시작했다. OS 파일 캐시는 유지했고 사본 준비와 검산은 측정 시간에서 제외했다.

180쌍에서 원본 관측·재사용 수, 토큰 합계, SQLite 논리 행과 네 조회 결과가 일치했다. 최초 수집과 한 건 추가의 제공자별 토큰을 독립 JSONL 집계로 검산했다. 모든 무변경 갱신은 본문 0바이트를 읽었고 저장·조회 결과는 시드 DB와 일치했다. SQLite 무결성과 외래 키를 확인했다. [원시 A/B 표본](RefreshHeapAB-2026-11-26.json)

실로그 최초 수집의 집계 직전 힙과 전체 피크는 모두 20쌍에서 낮았고 중앙값은 각각 23.5%, 2.6% 줄었다. 최초 수집 RSS의 범위는 A 363.27–452.53 MiB, B 395.48–456.09 MiB로 겹쳤다. 합성 10,000건은 집계 직전 힙이 14.10 → 12.14 MiB로 19쌍에서 낮았으며 전체 피크 중앙값은 17.75 → 18.06 MiB였다. 합성 100건의 최초 수집 피크는 8.12 → 8.06 MiB였다. 갱신·조회 시간의 관측 범위는 대부분 겹쳤다.

## 공개 통계 Worker 프로파일

실로그 한 사본에서 최초 수집, 통계 조회, 무변경 갱신 5회를 실행하는 경량 계측을 A/B 각각 5회 수행했다. 최초 수집의 통계 Worker 피크 중앙값은 **29.78 → 29.35 MiB**였다. 이어진 첫 무변경 갱신의 피크는 **24.71 → 30.75 MiB**였다. B는 첫 무변경 갱신 시작부터 더 높은 힙이 관측됐다. 예를 들어 첫 표본의 잠금 단계는 A 14.46 MiB, B 25.72 MiB였고 그 갱신이 끝난 뒤 강제 GC 값은 9.81 → 9.80 MiB였다. 측정한 시점의 힙은 이전 수집·조회에서 아직 회수되지 않은 객체도 포함한다.

별도 생존 할당 표본에서 실로그의 Codex 응답 **19,526행**을 모두 합산하는 상태에서 집계 직전 색인에 들어간 행이 **19,526 → 27개**로 줄었다. 그 시점의 강제 GC 후 힙은 **20.97 → 17.89 MiB**였다. 별도 누적 할당 표본에서 `walk`와 경로 관측 호출에 귀속된 합계는 **55.91 → 50.41 MiB**였다. 누적 할당에는 GC가 회수한 객체도 포함되며 수치별로 한 쌍을 관측했다. 힙 계측은 V8 `heapUsed`와 5ms 간격 및 단계 경계를 사용했다. VS Code 확장 호스트 전체와 Webview는 미측정이다. [원시 Worker 프로파일](RefreshHeapProfileAB-2026-11-26.json)

최초 수집에서 확인한 힙 절감과 복사본·누계 검증에 필요한 응답 키 수 감소를 근거로 두 변경을 적용했다. 무변경 피크 힙 상승과 최초 수집 RSS 범위는 위 조건에서 관측한 트레이드오프다. 타입 검사·린트·diff 검사를 통과했다. 일반 자동 테스트는 미실행이다.

## 재실행

제품 A/B 실행에는 변경 전 `src`, `localization`, `tsconfig.json`을 포함한 작업 트리 사본과 실로그·합성 입력의 기존 고정 스냅샷을 전달한다. 출력 위치는 사용하지 않은 파일을 지정한다. 소스·빌드·입력 SHA-256은 원시 JSON에 있다.

```powershell
node --no-warnings tests/benchmarks/thread-token-buffer-ab.cjs --base-source='<변경 전 소스 사본>' --input-workspace='<고정 스냅샷 폴더>' --unchanged=true --output=tests/results/benchmarks/RefreshHeapAB-rerun.json
node --no-warnings tools/diagnostics/summary-heap-profile.cjs --workspace='<첫 명령이 출력한 Workspace>' --reference=tests/results/benchmarks/RefreshHeapAB-rerun.json --dataset=real --variant=both --timeline-runs=5 --skip-quota=true --output=tests/results/benchmarks/RefreshHeapProfileAB-rerun.json
```
