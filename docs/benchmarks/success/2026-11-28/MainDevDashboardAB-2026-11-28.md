## 2. Heap·RSS·SQLite

## 4. 조건과 결과 대조

- Windows x64, Ryzen 5 7500F, VS Code 1.148.0, 확장 호스트 Node 24.22.1 및 SQLite 3.53.4를 사용했다. 전용 VS Code 프로필로 실제 통계 패널을 열었고 Worker·스키마 초기화와 DB 사본 준비를 마친 뒤 계측을 시작했다. 범위는 서울 기준 2026-10-30~11-28이며 양쪽 날짜 필터에서 날짜 미상은 제외했다. 두 제공자와 도구 수집을 켰으며 비용 표시는 기본값인 끔으로 뒀다. 조건별 준비 3쌍 후 실행 순서를 교대해 10쌍씩, 총 90쌍을 쟀다. OS 파일 캐시는 유지했다. 설치·이관 시간은 미측정이다.
- 실로그는 두 제공자의 795파일과 검증용 Claude 1파일, 총 561,942,065바이트다. 합성 입력은 Claude로 구성했고 10,000건은 500세션에 20건씩, 100건은 10세션에 10건씩 넣었다. 최근 기간에는 각각 200건과 10건이 들어간다. 1건 추가는 같은 Claude 파일 끝에 입력 100·출력 10토큰을 추가했다. 실로그 조건에서 다시 읽은 본문은 양쪽 모두 896바이트였다. 큰 Codex 로그의 증분 지연은 이번 화면 측정에서 재지 않았다.
- 모든 표본에서 화면 표가 표시됐고 파싱 실패·중단이 없었다. 합성 입력의 전체·최근 대화 수와 토큰 합계가 생성값과 일치했고 일·월·세션·프로젝트의 조회 그룹 수도 양쪽이 같았다. 두 빌드와 세 입력 모두 1건 추가 후 대화 1건과 110토큰이 늘었다. 개별 행의 평균값과 실로그의 초기 토큰 절대값은 독립 파서로 대조하지 않았다.
- 실로그의 초기 대화 수는 **전체 1,891건, 최근 1,042건**으로 같았다. 전체 토큰은 **3,947,715,560 → 3,936,973,672**, 최근 표 토큰은 **2,354,734,073 → 2,354,558,879**였다. 두 버전의 토큰 처리와 파싱 규칙에 변경이 있고 이번 계측으로 10,741,888토큰의 전체 차이를 원인별로 분해하지 않았다. 실로그 시간은 각 버전이 해당 로그를 화면에 띄우는 실제 경로의 관측값이다.
