# 일별 삭제·도구·결제 SQL A/B 테스트

사용자는 실행 계획을 바탕으로 적용한 SQL 변경의 처리 시간과 결과를 확인해 달라고 요청했다. 영향 세션으로 삭제를 제한하면 넓은 일별 표에서 탐색이 줄고, 도구와 결제 조회에서 원본과 세션을 반복 탐색하는 비용도 줄 것으로 예상했다.

A는 `4d3093d`의 v31 코드다. B는 같은 커밋에 일별 삭제 범위 제한, 도구 탭의 분류 일괄 조회, 세션 결제 조인을 적용한 작업 트리다. 두 소스와 빌드의 SHA-256은 원시 결과에 남겼다.

2026-11-28 18:46–18:50(서울), Windows x64, Ryzen 5 7500F, Node 24.14.1, SQLite 3.51.2에서 실행했다. Claude 12개와 Codex 765개의 원본 537,981,649바이트를 복사했다. 합성 입력은 고정 산식으로 생성했으며 두 제공자를 절반씩 사용한다. 세션당 대화는 1만 건에서 50개, 100건에서 5개다. 합성 도구 표에는 모델 집계만 있다.

입력마다 준비 3쌍 뒤 A→B와 B→A를 교대해 각각 10쌍을 측정했다. 요청 추가는 같은 사전 DB를 매번 복원하고 파일 확인부터 갱신 반환까지 측정했다. 파일·DB 사본 준비와 검산은 타이머 밖이다. OS 파일 캐시를 유지했다. 도구·비용 조회는 2026-10-30~11-28(서울)의 첫 100행을 조회했고, 프로세스별로 4회 준비한 후 64회 평균을 한 표본으로 삼았다. 일반 평균 토큰은 전체 기간의 모든 페이지를 읽고 완료 대화를 분모로 사용했다. 최초 수집은 사전 DB를 만드는 데 수행했으며 그 시간은 비교하지 않았다.

## 2. 정합성과 분석

- 세 입력의 60개 측정쌍과 9개 준비쌍에서 저장 토큰과 대화 수, 일별·모델별·도구별 행, 이름과 원본 상태, 네 평균 조회와 비용 조회 결과가 일치했다. SQLite 무결성과 외래 키 검사를 통과했다. 합성 입력의 전체 토큰은 생성기의 산식과 일치했다. 실로그와 합성 입력 모두 추가분은 독립 원본 검산과 같은 1대화·입력 123·출력 7토큰이었다. 실로그의 초기 전체 토큰 절대값은 독립 대화 단위로 검산하지 않았다.
- 도구 순위·비율·분류별 페이지·빈 후속 페이지를 저장된 일별 행에서 JavaScript로 별도 계산해 대조했다. 별도 사례에서는 삭제 대상 세션과 동일한 ID를 쓰는 다른 제공자의 행, 소실 보존 날짜, 기존 날짜·프로젝트·모델 삭제, 결제 미지정·명시 미상·세션 이름 행이 없는 경우를 확인했다. 도구 페이지와 결제 변경의 기존 Worker 테스트 두 건도 A/B에서 각각 통과했다.
- 도구 탭은 실로그·1만·100건 모두 20쌍에서 빨랐다. 원본 탐색이 네 곳에서 한 곳으로 줄었고, 비용 조회는 세션 키 조인으로 같은 결제값을 공유한다. 비용을 끈 일반 평균 조회의 중앙값 변화는 약 −3~+3%였다.
- 요청·모델 삭제는 실로그 18/20쌍과 1만 건 20/20쌍에서 빨랐으며 100건은 20쌍 모두 느렸다. 실행 계획은 바깥 테이블 스캔에서 세션 PK 탐색으로 바뀐다. 작은 DB에서 늘어난 약 0.18ms에는 영향 세션 목록을 만드는 비용이 영향을 줬을 수 있으며, 그 비용은 별도로 측정하지 않았다. 실로그와 100건의 전체 추가 시간은 쌍별 차이의 사분위 범위가 0을 포함했다. 1만 건의 전체 추가는 16/20쌍에서 빨랐다. [원시 표본](SQLiteWorkReductionAB-2026-11-28.json)
