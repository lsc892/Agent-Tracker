# 최종 요약 문자열 정렬의 임시 버퍼 A/B

최종 대화·모델·Skill 정렬에서 비교마다 만드는 UTF-8 버퍼를 줄이면 집계 힙이 줄어들 것으로 가정했다. A는 현재 작업 트리다. B는 두 문자열이 같으면 바로 0을 반환하고, 서로게이트 코드 단위가 없는 두 문자열은 JS 문자열 비교를 사용한다. 그 밖에는 기존 UTF-8 바이트 비교를 적용한다. 서로게이트가 없는 문자열에서 두 표현의 순서는 같고, 보충 평면 문자와 잘못 짝지어진 서로게이트에는 기존 비교 규칙을 사용한다. [현재 비교 함수](../../../../src/summary/aggregation/turns.ts#L32)

## 측정 조건

Windows x64, Ryzen 5 7500F, Node 24.14.1, SQLite 3.51.2, Asia/Seoul, 파일 워커 최대 4개다. 실로그 751파일·506,096,130바이트와 Claude·Codex 반씩인 두 합성 입력으로, 빈 DB와 대화 한 건을 더한 기준 DB 사본을 각각 준비 3쌍, 측정 AB·BA 10쌍씩 실행했다. OS 캐시는 유지했다. 힙은 수집 스레드를 5 ms 및 단계 경계에서 관측했다. 추가 후 평균 쿼리는 완료 대화를 분모로 전체 페이지를 읽었다.

총 120쌍의 SQLite 대화·모델·Skill·원본 상태와 네 조회 결과가 일치했다. 합성 결과는 입력 기대값, 추가 1대화·130토큰은 추가한 원본과 대조했다. SQLite 무결성 및 외래 키 검사도 통과했다.
