# 작은 JSONL 파일의 일괄 읽기 A/B

사용자는 작은 파일을 통째로 읽어 긴 줄을 조립하는 복사와 문자열 사전 검사를 줄이고, 큰 파일은 기존 청크 방식으로 처리한 뒤 전체 수집 시간·RSS·V8 힙을 비교하도록 요청했다.

- **A · 현재 방식** `16ef235`. 본문을 최대 64 KiB씩 읽고, 조립이 필요한 줄은 파일별 버퍼를 재사용한다.
- **B · 작은 파일 일괄 읽기** `perf/small-jsonl-whole-file`의 `fe417d7`. 압축 해제 후 4 MiB까지 파일을 버퍼에 모은다. 한도를 넘는 Zstd 파일은 이미 해제한 청크부터 기존 파서에 넘긴다. 작은 파일에서는 버퍼에서 LF 위치를 찾아 한 줄씩 디코딩하고, 기존 필드 선택기가 문자열 경계를 검사하는 동안 이미지 본문 범위도 기록한다. 선택한 값은 그 범위를 제외해 해석한다. 늦게 나온 `type`과 지연 해석은 기존 선택기 규칙을 따른다.

## 실로그 최초 수집

실로그 751파일·506,096,130바이트·1,731대화를 수집한 20쌍의 중앙값이다. A와 B의 상대 변화는 B가 커지면 양수로 표기한다.

| 지표 | A | B | 변화 |
| --- | ---: | ---: | ---: |
| 최초 수집 전체 | 3,781.10 ms | 3,695.66 ms | −2.3% |
| 로그 읽기·파싱 | 3,398.37 ms | 3,313.11 ms | −2.5% |
| 프로세스 피크 RSS | 836.60 MiB | 879.44 MiB | +5.1% |
| 파일 워커 V8 힙 피크 | 67.98 MiB | 72.81 MiB | +7.1% |
| 파일 워커 `ArrayBuffer` 피크 | 60.18 MiB | 64.40 MiB | +7.0% |
| 수집 스레드 V8 힙 피크 | 70.07 MiB | 70.07 MiB | 0.0% |

최초 수집과 읽기·파싱은 각각 18쌍에서 빨랐다. 피크 RSS는 19쌍에서 높았고, 파일 워커 V8 힙과 `ArrayBuffer` 피크는 각각 17쌍에서 높았다. 전체 파일 버퍼와 압축 해제 청크의 보유 시간이 늘었으며, 전체 RSS 증가분의 구성별 기여도는 미측정이다. 절감한 시간과 늘어난 메모리를 함께 고려해 A를 유지했다.

## 합성 입력과 대화 한 건 추가

각 셀은 A → B 중앙값이다. 평균 조회는 대화 한 건을 추가한 DB에서 그룹별 전체 페이지를 읽는 시간이다.

| 지표 | 실로그 1,731대화 | 합성 10,000대화 | 합성 100대화 |
| --- | ---: | ---: | ---: |
| 최초 수집 전체 (ms) | 3,781.10 → 3,695.66 | 829.47 → 824.22 | 49.68 → 50.31 |
| 최초 수집 피크 RSS (MiB) | 836.60 → 879.44 | 186.00 → 185.73 | 57.45 → 57.52 |
| 최초 수집 스레드 V8 힙 피크 (MiB) | 70.07 → 70.07 | 80.18 → 79.48 | 10.31 → 10.35 |
| 대화 한 건 추가와 커밋 (ms) | 267.67 → 268.40 | 63.13 → 64.83 | 36.44 → 37.38 |
| 대화 한 건 추가 피크 RSS (MiB) | 72.04 → 72.42 | 56.34 → 56.42 | 54.10 → 54.01 |
| 대화 한 건 추가 시 V8 힙 피크 (MiB) | 13.09 → 12.92 | 8.84 → 8.86 | 7.71 → 7.73 |
| 일별 평균 토큰 조회 (ms) | 1.956 → 1.916 | 1.257 → 1.224 | 1.031 → 1.108 |
| 월별 평균 토큰 조회 (ms) | 0.908 → 0.923 | 0.522 → 0.615 | 0.417 → 0.398 |
| 세션별 평균 토큰 조회 (ms) | 3.978 → 3.789 | 1.629 → 1.566 | 0.560 → 0.536 |
| 프로젝트별 평균 토큰 조회 (ms) | 1.087 → 1.144 | 0.551 → 0.552 | 0.453 → 0.398 |

합성 입력과 대화 한 건 추가에서는 파일 준비가 수집 스레드에서 실행됐다. 전체 시간과 메모리의 중앙값 차이는 실로그 최초 수집보다 작았다.

## 정합성

Skill 수집 켜짐·꺼짐 각각에서 실로그 237,821줄과 합성 30,100줄·310줄의 추출 속성·값 및 원본 오프셋 해시가 일치했다. 120쌍의 SQLite 테이블·토큰 합계·Skill·이름·원본 상태와 일·월·세션·프로젝트 조회 결과가 일치했다. 합성 최초 수집은 입력 생성기의 대화·토큰 합계와 일치했고, 모든 입력에서 대화 한 건을 추가한 뒤 1대화·130토큰이 늘었다. 평균은 일별 집계 행의 완료 대화와 토큰을 별도로 합산해 검산했다. 두 빌드의 컴파일과 후보의 변경 파일 린트를 확인했다.

## 측정 조건과 재실행

- Windows x64, Ryzen 5 7500F, Node 24.14.1, SQLite 3.51.2, Asia/Seoul. 파일 워커 최대 4개, Skill 수집 켜짐, OS 파일 캐시 유지 조건이다. 실로그 751개 중 압축 해제 크기 4 MiB 이하 파일은 686개였다.
- 최초 수집은 새 DB에서, 대화 1건 추가는 같은 기준 DB 사본에서 각각 준비 3회 후 AB·BA 10회씩 실행했다. 저장 커밋과 워커 종료를 경과 시간에 포함했다. V8 힙과 워커 버퍼는 5ms 간격과 작업 경계에서 관측했다. 표의 파일 워커 메모리는 회차별 가장 높은 워커 피크의 중앙값이다.
