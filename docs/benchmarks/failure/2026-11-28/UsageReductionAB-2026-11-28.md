## 3. 복잡도와 판정

- **필드** — JSONL 입력이 `B`바이트일 때 문법 확인은 전후 `O(B)`다. 요청 본문에 대한 추가 제목 정규화와 플래그의 보관·전송을 생략했다. 실로그 집계 스레드 피크 힙은 20쌍 모두 줄어 중앙값이 52.27 → 50.60 MiB였다. 파일 준비 Worker 네 개 중 가장 높은 힙을 별도로 표본 조사한 결과는 63.35 → 64.51 MiB로, 6쌍 중 3쌍에서 줄었다. 이 진단은 20 ms 간격과 준비 1쌍을 사용했다. 합성 1만 건은 집계 직전 힙이 43.50 → 36.74 MiB, 직후가 52.62 → 46.63 MiB로 줄었지만 저장까지 포함한 피크는 63.57 → 90.53 MiB로, RSS는 167.05 → 182.84 MiB로 늘었다. 완료 후 강제 GC 뒤의 중앙값은 두 구현 모두 7.92 MiB였다. 피크 증가의 GC 시점과 할당 원인은 별도로 분리하지 않았다. 실로그 전체 시간의 쌍별 차이 가운데 50%는 −30.36~+22.87 ms였다. 전체 메모리 개선 기준으로는 보류했다.
- **캐시 보정** — 확정 응답 `N`개 중 누계 검산 대상이 `C`개면 제품 경로의 캐시 범위 보정은 `N + C`회에서 `N`회로 줄고, 대상마다 `Math.min/max` 세 호출을 생략한다. 상한은 전후 `O(N)`, 추가 공간은 `O(1)`이다. 세션별 응답 정렬의 최악 상한은 `O(N log N)`다. 실로그 집계는 63.14 → 63.49 ms, 1건 추가는 251.90 → 252.44 ms였다. 시간·메모리·DB 크기의 일관된 개선이 관측되지 않아 보류했다.
- **SQLite** — 세션 `S`행과 결제 지정값 `K`행을 별도 저장하던 구조를 세션 `S`행으로 통합했다. `K ≤ S`이므로 저장 공간의 점근 차수는 전후 `O(S)`다. 명시값의 키 탐색은 `O(log(K+1))`에서 `O(log(S+1))`로 바뀌며 값이 없으면 일별 기본값을 검토한다. 테이블은 8 → 7개, 새 DB는 세 규모 모두 4 KiB 줄었다. 기존 DB를 이관한 뒤 주 파일 크기는 같았고 4 KiB가 재사용 가능 페이지가 됐다. 이관을 포함한 첫 열기는 실로그·1만·100건 순으로 15.36·14.98·14.68 ms였다. 실로그 1건 추가 중앙값은 +1.8%, 합성 1만 건 전체 모델 비용 조회는 +8.6%였다. 공간 절감과 이관 비용을 고려해 별도 브랜치에 보관했다.
