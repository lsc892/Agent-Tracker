# 진단·개수·소실 원본 조회 A/B

사용자는 EXPLAIN에서 찾은 세 곳을 각각 브랜치에서 비교해 달라고 요청했다. 진단 재조회와 개수 조회의 결제 조인을 생략하면 해당 조회가 빨라질 것으로 예상했다. 소실 원본 쿼리는 자동 인덱스 생성과 제공자 범위 탐색 중 어느 쪽이 싼지 비교했다.

기준 A는 `e7cba67`이다. 같은 커밋의 세 로컬 worktree에서 후보를 하나씩 구현했다.

## 2. 정합성과 판정

- 세 규모의 60개 측정 묶음에서 기준과 각 후보를 180쌍 비교했다. 저장된 대화 수·토큰·일별 상태와 네 평균 조회·비용·집중 조회 결과가 일치했다. 합성 입력 전체 토큰은 생성 산식과 일치했고, 세 입력의 추가량은 독립 검산과 같은 1대화·입력 123·출력 7토큰이었다. 실로그 초기 전체 합계의 독립 대화 단위 검산은 수행하지 않았다.
- 오류·중단과 중복 파일이 있는 세션, 제공자 범위와 미귀속 파일, 결제 지정 상태에서의 NULL·빈 모델과 빈 후속 페이지, 소실 원본의 날짜 보존을 별도 사례로 검증했다. 기준과 세 후보 모두 통과했다.
- 진단은 실로그 19/20쌍에서 빨랐고, 실행 바이트코드에서 두 번째 원본 조회를 건너뛰는 분기를 확인했다. 오류·중단 파일이 있는 경우의 시간은 별도로 측정하지 않았다.
- 개수 후보는 결제 PK 탐색을 없앴다. 개수만 재면 실로그에서 제공자별 18.9%, 모델별 21.7% 단축됐다. 빈 후속 페이지는 행을 조회하는 첫 SQL도 실행하므로 전체 단축은 8.1%였다.
- 소실 원본 후보는 자동 부분 인덱스를 없앴지만 실로그의 두 영향 범위와 합성 1만 건에서 시간이 늘었다. 제공자·경로 인덱스에서 제공자 범위를 읽고 세션 키를 대조하는 계획으로 바뀌었다. 본 후보는 100건·16세션에서만 빨랐다. 세 후보 모두 전체 요청 추가 시간의 쌍별 차이 사분위 범위가 0을 포함했다.
- 진단과 개수 조회를 반영할 근거가 있고, 소실 원본 후보는 현재 SQL을 유지할 근거가 있다. 제품에는 병합하지 않았으며 실험 변경은 세 worktree에 보관했다.
